# configs/ — 이름 짓는 규칙

`pipelines/` 는 무엇을 재는지(부품과 커밋 정책), `datasets/` 는 무엇을 먹이는지(데이터와 목표
언어)를 적는다. 파일 이름이 곧 설정 이름이고, bench 는 실행을 `bench/runs/<데이터셋>/<파이프라인>/`
에 둔다. 설정 안의 키는 [bench/README.md](../bench/README.md) 의 '설정' 절에 있다.

**이름만 보고 무엇인지 알 수 있어야 한다.** 그래서 이름에는 비교할 때 갈리는 것만 넣고, 나머지는
파일 안에 둔다. 이름에 모든 값을 넣으려 하면 읽을 수 없어지고, 그래도 빠지는 값이 생긴다.

## 이름의 모양

| 종류 | 칸 (이 순서로) | 예 |
|---|---|---|
| 데이터셋 | `코퍼스_방향[_조건][_부분]` | `fleurs_ko-en`, `fleurs_ko-en_cafe`, `fleurs_ko+en-en_lvl26`, `fleurs_en-ko_top50` |
| 파이프라인 | `역할.모델[+역할.모델…][_변형]` | `asr.qwen-seg-ko+mt.qwen3.5-4b`, `mock` |

기호마다 할 일이 하나씩이다.

| 기호 | 뜻 |
|---|---|
| `_` | 칸을 나눈다 |
| `+` | 한 칸 안에서 여럿을 잇는다 (파이프라인의 부품들, 섞인 언어들) |
| `-` · `.` | 값 안에서만 쓴다 (`ko-en`, `qwen3.5-4b`, `asr.`) |
| `@v<N>` | 버전. 파일 이름에는 쓰지 않는다 — `meta.version` 에서 붙는다 |

- 소문자, 숫자, `. + -` 만 쓴다. bench 가 시작할 때 검사한다.
- 언어는 두 글자 코드로 쓴다 (`ko`, `en`). 데이터 디렉토리의 `ko_kr` 같은 이름은 설정 안에만 둔다.
- 기본값은 칸을 두지 않는다. 깨끗한 오디오면 조건 칸이 없고, 전부 돌면 부분 칸이 없다.
- 부품 이름은 코드의 레지스트리 이름 그대로 쓴다 (`qwen-seg`, `qwen3.5`). 그래야 검색된다.
- 부품 버전 `:v<N>` 은 `:` 를 빼고 `-v<N>` 으로 쓴다 — `qwen-seg:v2` 는 `asr.qwen-seg-v2-en`. 파일 안의 `name:` 은 레지스트리 이름(`qwen-seg:v2`) 그대로다.

### 칸에 쓰는 말

새 말을 만들기 전에 여기 있는 것을 먼저 쓴다. 새로 만들면 여기 한 줄 더한다.

| 칸 | 말 | 뜻 |
|---|---|---|
| 조건 | `cafe` | 카페 소음 (`augment.noise.place: cafe`) |
| 조건 | `hall` | 공연장 울림 (`augment.room.place: hall`) |
| 조건 | `lvl26` | 턴마다 −26 dBFS 로 맞춘 데이터 (`mix.py --level -26`) |
| 부분 | `top<N>` | 가장 긴 N개 (`limit: N`, `pick: longest`) |
| 부분 | `first<N>` | 앞의 N개 (`limit: N`) |
| 역할 | `asr.` · `mt.` | 음성 인식, 번역 |

## `meta` 블록

실행이 하는 일은 바꾸지 않고 설정을 설명만 한다. 모든 키가 선택이다.

```yaml
meta:
  version: 2            # 기본 1. 1 이면 이름에 붙지 않는다
  description: FLEURS Korean sentences with cafe noise; quiet clips raised to -23 dB
  tags: [fleurs, sentence, noise]
dataset:
  ...
```

- `description` 은 이름에 없는 것을 적는다 — 소음 세기, 음량 바닥, 어떤 모델 파일인지.
- `tags` 는 대시보드에서 실행 옆에 나온다. 여러 설정을 가로지르는 묶음에 쓴다 (`noise`,
  `longform`, 논문에 쓰는 실행이면 `paper`). 나중에 붙여도 된다 — 대시보드는 지난 실행에도
  지금 파일의 태그를 보여 준다(버전이 같을 때).
- `description`·`tags` 는 설정의 해시에 들어가지 않는다. 고쳐도 버전을 올릴 필요가 없다.

## 버전 — 이름의 뜻은 바뀌지 않는다

**실행이 있는 이름은 계속 같은 것을 가리켜야 한다.** bench 는 실행마다 두 설정의 해시(`meta` 를
뺀 내용)와 데이터셋 manifest 의 해시를 남긴다. 같은 이름·같은 버전으로 전에 돈 실행과 둘 중 하나라도
다르면 시작하기 전에 멈춘다.

그때 할 일은 둘 중 하나다.

- 뜻이 바뀐 것이 맞으면 `meta.version` 을 올린다. 실행은 `<이름>@v<N>` 으로 따로 쌓이고, 지난
  버전의 결과는 그대로 남는다.
- 실수로 바뀐 것이면 파일(또는 데이터)을 되돌린다.

버전을 올리는 대신 새 이름을 지을 때도 있다 — 비교하려는 조건 자체가 새것이면(소음 종류, 부분
집합) 이름에 칸을 더하는 쪽이 맞다. 같은 조건을 고쳐 다시 재는 것이면 버전이다.
