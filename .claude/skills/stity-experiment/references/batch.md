# 이 머신에서 배치 — `make bench-batch`

`scripts/bench/batch.sh` 가 목록 파일을 한 줄씩 읽어 이 머신에서 `make bench` 를 차례로 돌린다. 여러 조합을
GPU 머신에서 돌리는 기본 길은 머신의 queue 에 조합마다 job 을 넣는 것이다([queue.md](queue.md)).

## 목록 파일

```
# 주석과 빈 줄은 건너뛴다
asr.qwen-seg-en+mt.qwen3.5-4b fleurs_en-ko
asr.qwen-seg-ko+mt.qwen3.5-4b fleurs_ko-en_cafe
```

- 한 줄에 `파이프라인 데이터셋` 하나. 공백으로 나눈다.
- 데이터셋이 빠진 줄은 돌리지 않고 실패로 센다.
- 배치 실행이면 고른 파이프라인 × 데이터셋 조합으로 `logs/bench/<tag>.txt` 를 만든다. 방향이 안 맞는 조합(영어 ASR
  파이프라인 × 한국어 데이터셋)은 4단계 설명에 따로 표시한다. 빼지는 않는다 — 언어가 섞인 데이터셋을 한 모델로 재는
  것처럼 일부러 그러는 경우가 있다.
- 사용자가 준 목록 파일의 기존 줄은 고치지 않는다. 형식이 틀렸으면 4단계 설명에 적는다.

## 실행

[run.md](run.md) 의 tmux 스크립트에서 `make bench` 줄을 이렇게 바꾼다.

```bash
if make bench-batch LIST=<목록 파일>; then touch "$tag.done"; else touch "$tag.failed"; fi
```

하나가 실패해도 다음 줄로 넘어간다. 하나라도 실패하면 끝에 `.failed` 가 생긴다 — 나머지는 성공했을 수 있다.

## 도는 배치에 추가하기

`batch.sh` 는 목록 파일을 처음에 다 읽지 않고 한 줄씩 읽는다. 그래서 **도는 중인 배치의 목록 끝에 줄을 더하면 그 배치가
이어서 돌린다.** 마지막 줄의 실행이 끝나기 전에 더해야 한다.

1. 배치가 정말 도는지 본다 — `.done`·`.failed` 가 없고 `tmux has-session -t bench-<시각>` 이 성공해야 한다.
   끝났으면 더하지 않고 새 배치로 띄울지 묻는다 ([questions.md](questions.md) "5. 확인").
2. 같은 줄이 이미 있거나 이미 돈 줄이면 더하지 않고 알린다.
3. 파일이 줄바꿈으로 끝나지 않으면 줄바꿈부터 붙인다. 안 그러면 마지막 줄과 붙어 버린다.
   ```bash
   [ -n "$(tail -c1 <목록 파일>)" ] && echo >> <목록 파일>
   echo "<파이프라인> <데이터셋>" >> <목록 파일>
   ```
4. 로그의 마지막 `===` 줄로 지금 몇 번째 실행인지 보고, 남은 줄 수로 이 줄에 언제쯤 닿을지 알린다.
   이 세션이 지켜보던 배치가 아니면 지켜보지 않는다. 로그 경로만 알려 준다.

## 지켜보기와 보고

- 실행마다 `=== <시각> <파이프라인> × <데이터셋>` 줄로 시작한다. 이 줄로 지금 몇 번째 실행인지 알린다.
- 끝에 `=== <시각> finished, N failed` 와 `failed: ...` 줄이 나온다. 실패한 것만 따로 보고한다.
- 성공한 실행은 [run.md](run.md) 의 "결과 보고" 를 표 하나로 모아 보여 준다 (행: 실행, 열: 지표).
