# 질문 묶음

`AskUserQuestion` 은 한 번에 질문 4개, 질문마다 선택지 4개까지다. "기타"는 도구가 늘 붙여 주므로 선택지로 만들지
않는다. 선택지가 모자라면 아래 "고르는 순서" 로 앞의 것만 보여 주고, 나머지는 기타에 이름이나 검색어를 받는다.
헤더는 12자 이내로 짧게 쓴다.

## 고르는 순서 — 설정이 수백 개여도 된다

데이터셋 설정을 고를 때 쓴다. 목록 전체를 보여 주지 않는다. 사용자가 지금 작업 중일 가능성이 높은 순서로 3개만 고르고,
네 번째 자리는 "단계별로 고르기" 에 쓴다. 파이프라인은 말로 받지만, 비슷한 설정이 여럿이면 이 순서로 앞선 것을 쓴다.

```bash
make configs-pull   # 1. "unpushed" 로 찍힌 것 — 여기서 고쳤고 아직 S3 에 안 올림
make configs-list   # 2. S3 에서 최근에 바뀐 순 (종류 칸으로 dataset / pipeline 을 거른다)
```

- 이 순서로 합치고 겹치는 것은 뺀다. 선택지 설명에 어디서 왔는지(`안 올림`·`최근 수정`)와
  `meta.description` 을 짧게 붙인다.
- **기타에 적힌 것은 이름 또는 검색어다.** 정확히 같은 파일이 있으면 그것을 쓴다. 이름에 그 말이 들어간 파일이 여럿이면
  같은 고르는 순서로 최대 4개를 보여 주는 질문을 한 번 더 한다. 하나도 없으면 비슷한 이름을 보여 주고 다시 묻는다.

## 1. 실행 형태

| 질문 | 선택지 |
|---|---|
| 어떻게 돌릴까요 | 머신의 queue 에 넣기 (권장 — 고른 GPU 머신이 시간표대로 돌리고 결과를 팀이 manager 에서 봄) / 이 머신에서 한 번 (`make bench`) / 이 머신에서 배치 (`make bench-batch`, 여러 조합을 차례로) / 도는 배치에 실험 추가 |

**머신의 queue 에 넣기** 는 `.env` 에 `STITY_S3_BUCKET` 이 있을 때만 보여 주고, 그때는 첫 선택지로 둔다. 고르면 5단계의
스모크 테스트와 "실행 방식" 을 묻지 않고 [queue.md](queue.md) 를 따른다. 여러 조합이면 조합마다 job 하나씩 넣는다.

**이 머신에서 돌리는 셋** 을 고르면, 진행하기 전에 queue 와 다른 점을 한 번 알린다 — 그 머신의 queue 를 거치지
않아 같은 GPU 의 queue job 과 부딪칠 수 있고, 다른 사람에게는 결과가 올라오기 전까지 안 보이며, tmux 로
직접 지켜야 한다. 결과는 queue 로 돈 실행과 똑같이 S3 에 올라간다. 사용자가 그래도 고르면 그대로 진행한다.

**도는 배치에 추가** 면 같은 단계에서 어느 배치인지 바로 묻는다. 후보는 `logs/bench/*-batch.txt` 를 최근 것부터 보여 주고,
설명에 상태를 붙인다 — `.done`·`.failed` 가 없고 tmux 세션 `bench-<시각>` 이 살아 있으면 "도는 중", 아니면 "끝남".
기타에 다른 목록 파일 경로를 받는다.

## 2. 파이프라인 — 하고 싶은 실험을 말로 받는다

선택지를 주지 않는다. `AskUserQuestion` 을 쓰지 않고 채팅으로 한 번 묻고 답을 기다린다.

> 어떤 실험을 하고 싶은지 적어 주세요. 예: "qwen-seg:v2 로 영어 커밋 정책을 punct 로 바꿔서", "지금 영어 파이프라인 그대로".

배치나 머신의 queue 면 여러 실험을 한 번에 적어도 된다고 덧붙인다.

### 뜻을 풀어 맞는 설정을 찾는다

1. **답을 설정 값으로 바꾼다.** 부품(`pipeline.transcription.name` 등), 모델, `commit`, VAD 값처럼 파일에 들어갈 값으로 적는다.
   - 부품은 레지스트리 이름으로 맞춘다. `core/components/`·`core/pipeline/` 에서 `.register(` 로 찾는다 —
     `qwen-seg`, `qwen-seg:v2` 처럼 버전까지 그대로.
   - 말하지 않은 값은 가장 가까운 기존 설정의 값을 물려받는다.
2. **내용으로 찾는다, 이름으로 찾지 않는다.** `configs/pipelines/*.yml` 을 읽어 1번의 값과 `meta` 를 뺀 내용을 비교한다.
   수백 개여도 grep 으로 부품·모델 이름을 먼저 좁힌 뒤 읽는다.
3. **결과를 알린다.** 묻지 않고 다음 단계로 간다 — 틀렸으면 5단계 확인에서 고칠 수 있다.
   - **맞는 설정이 있으면** 그 이름과 `meta.description` 을 알리고 그것을 쓴다.
   - **없으면** 무엇을 만들지 알린다. 바탕이 된 설정(값이 가장 많이 같은 것, 같으면 [고르는 순서](#고르는-순서--설정이-수백-개여도-된다)로
     앞선 것), 거기서 바뀌는 값, 새 파일 이름. 이름과 버전은 [configs.md](configs.md) 를 따른다. 파일은 4단계에서 쓴다.

### 되묻는 경우

뜻이 둘 이상으로 갈려 값이 정해지지 않을 때만 `AskUserQuestion` 으로 묻는다. 예: 어느 언어 모델인지(`-en`·`-ko`)
안 정해짐, 말한 부품이 레지스트리에 없음(비슷한 이름을 선택지로). 선택지는 그 갈림길의 후보들로 만든다.

## 3. 데이터셋

먼저 이미 있는 설정을 쓸지 묻는다. 있는 것을 고르면 3-1 이후는 건너뛴다.

| 질문 | 선택지 |
|---|---|
| 데이터셋 설정 | 고르는 순서의 3개 / 단계별로 고르기 |

배치나 머신의 queue 면 복수 선택으로 묻는다. 기존 것과 "단계별로 고르기" 를 같이 고를 수 있다.

### 3-1. 코퍼스

`make env` 로 `STITY_DATA_ROOT` 를 보고, 설치된 코퍼스를 찾는다.

```bash
find "$STITY_DATA_ROOT" -maxdepth 3 -name dataset.yml -not -path '*/.venv/*'
```

| 질문 | 선택지 |
|---|---|
| 코퍼스 | 설치된 것 중 `configs/datasets/` 에서 많이 쓰인 순서로 3개 (`fleurs`, `northstar-260928` …). 기타에 다른 코퍼스 |

- 같은 코퍼스가 언어별 디렉토리로 나뉘어 있으면(`fleurs/en_us`, `fleurs/ko_kr`) 여기서는 코퍼스만 고르고 3-2 에서 언어로 고른다.
- 설치 안 된 코퍼스면 `$STITY_DATA_ROOT/README.md` 의 표에서 받는 방법을 알려 주고 데이터셋 고르기를 멈춘다.
  `install.sh` 는 대신 돌리지 않는다 — 오래 걸리고, 승인이 필요한 코퍼스도 있다.

### 3-2. 언어

두 질문을 한 번에 묻는다. 선택지는 그 코퍼스의 `dataset.yml` 에서 만든다.

| 질문 | 선택지 |
|---|---|
| 원문 언어 | 언어별 디렉토리가 있으면 그 언어들, 아니면 `languages` (여럿이면 "섞인 그대로" 도 하나) |
| 번역할 언어 | `provides.translations` 의 언어들 |

`provides.translations` 에 없는 언어를 기타로 고르면 참조 번역이 없어 BLEU·COMET 이 안 나온다고 설명에 적는다.
고른 언어가 정해지면 `dataset.name`(`fleurs/en_us`, `northstar-260928`)을 확정한다.

### 3-3. 범위와 조건

| 질문 | 선택지 |
|---|---|
| 범위 | 전부 / 앞 N개 (`first<N>`) / 가장 긴 N개 (`top<N>`) / 발표 통째로 (`longform`) |
| N | 50 / 100 / 해당 없음 (기타에 다른 수) |
| 효과 (복수 선택) | 없음 / 소음 (`augment.noise`) / 공간 울림 (`augment.room`) / 최소 음량 (`augment.volume`) |
| 데이터셋 더 추가 | 이걸로 끝 / 하나 더 (배치나 머신의 queue 일 때만 묻는다) |

- `longform` 은 한 그룹의 항목이 모두 한 오디오 파일 안의 구간(`offset`)인 코퍼스만 된다 (bench/README.md 의 `longform` 절).
  아니면 선택지에서 뺀다.
- "하나 더" 면 3-1 부터 다시 묻는다.

### 3-4. 효과 값

3-3 에서 효과를 골랐을 때만 묻는다. 장소는 디렉토리 이름이다.

```bash
ls "$STITY_DATA_ROOT/augment/noise" "$STITY_DATA_ROOT/augment/room"
```

디렉토리가 없으면 효과 파일이 이 머신에 안 받아진 것이다. `$STITY_DATA_ROOT/augment/README` 의 받는 방법을 알려 주고,
그 효과는 빼고 진행하며 4단계 설명에 뺐다고 적는다.

| 질문 | 선택지 |
|---|---|
| 소음 장소 | `augment/noise/` 의 디렉토리 이름. 이미 설정에 쓰인 것(`cafe`)을 먼저 |
| 소음 크기 | 약하게 `[0.1, 0.3]` / 보통 `[0.1, 0.5]` / 세게 `[0.3, 0.8]` (말소리 대비 소음 크기 비율) |
| 울림 장소 | `augment/room/` 의 디렉토리 이름 (`hall` …) |
| 울림 정도 | 약하게 `[0.2, 0.5]` / 보통 `[0.5, 1.0]` / 전부 `1.0` (기기 소리 `phone` 은 전부) |

최소 음량은 묻지 않고 지금 설정들이 쓰는 `min_level_db: -23` 을 쓰고 설명에 적는다. 설정 하나에 장소는 하나다.

## 5. 확인

설명을 보여 준 뒤 한 번에 묻는다. 이 머신에서 돌릴 때는 **스모크 테스트를 매번 묻는다.** 머신의 queue 면
"이대로 실행할까요" 만 묻고, 넣을 머신과 branch 는 [queue.md](queue.md) 대로 묻는다.

| 질문 | 선택지 |
|---|---|
| 이대로 실행할까요 | 실행 / 고칠 것 있음 (기타에 내용) / 취소 |
| 스모크 테스트 | 실제 파이프라인 + `first5` 먼저 / `mock` + `first5` 먼저 / 안 함 |
| 실행 방식 | tmux 로 띄우고 에이전트가 지켜봄 / tmux 로 띄우고 넘김 / 이 세션에서 바로 (스모크 테스트만) |

- **도는 배치에 추가** 면 "실행 방식" 대신 묻지 않는다. 그 배치가 도는 중이면 목록 끝에 줄을 더하고([batch.md](batch.md)),
  끝났으면 그렇다고 알리고 이 줄들로 새 배치를 띄울지 "실행 방식" 을 묻는다.
- "고칠 것 있음" 이면 고친 뒤 설명을 다시 보여 주고 이 묶음을 다시 묻는다.
- "취소" 면 만든 설정 파일을 알려 주고 끝낸다. 지우지 않는다.
- 본 실행에 "이 세션에서 바로" 를 고르면 tmux + 지켜봄으로 띄우고 그렇게 했다고 알린다. 본 실행은 몇십 분 이상 걸린다.
