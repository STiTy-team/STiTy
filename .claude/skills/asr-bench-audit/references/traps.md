# 함정 목록 — 이 프로젝트에서 실제로 결론을 뒤집은 것들

전부 "모델 특성"으로 기록될 뻔했다가 측정 문제로 판명된 건이다.
수치와 재현 절차는 레포 `evaluation/backends/REPORT.md` 의 R1~R13 에 있다.

## 증상 → 먼저 볼 곳

| 증상 | 원인 후보 |
|---|---|
| 전 클립 빈 전사, 클라이언트는 `ConnectionClosedOK: 1000 (OK)` | 서버 OOM 으로 엔진 사망. **정상 종료로 보이는 게 함정** |
| 서버 로그엔 전사가 있는데 클라이언트 HYP 가 빔 | 후처리(번역)가 final 전송을 막고 있다. `grep -c AST-SEND` 가 0 |
| 특정 클립만 전사가 통째로 빔 | 입력 피크 확인. 0.005 근처에 임계가 있는 백엔드가 있다 |
| en 만 오류율이 두 배 | 조각 조립의 공백 오염. **ko 는 둔감해 안 보인다** |
| 전사가 정확히 두 번 반복 (CER ≈ 1.2) | `finish()` 의 누적본↔최종본 조정 로직 |
| 한 백엔드만 지연이 몇 배 | **출력 채널을 빼먹었는지부터** |
| 지연이 클립 길이에 비례 | "오디오 끝" 기준 자체 지표를 쓰고 있다 |
| 스윕했는데 두 설정 결과가 완전 동일 | 무효값이 조용히 기본값으로 떨어졌다 |
| 청크 경계 단어가 사라짐 | 청크마다 `generate()` 를 부르고 있다(캐시 리셋) |
| 한 백엔드만 오류율이 튐 | 숫자 표기(ITN) 규칙 차이 |

## 13건 요약

1. **정식 스트리밍 API** — 청크별 `generate()` 는 매 호출이 캐시를 리셋한다. 제너레이터를
   한 번 넘기는 방식을 찾을 것. 조용히 열화되므로 전사를 눈으로 봐야 잡힌다.
2. **기동 벽** — KV cache 예산, nvcc 부재로 인한 JIT 샘플러 실패, 프로토콜 필드 위치.
3. **기준선의 빈 전사** — 공용 GPU 경합이 아니라 (a) ASR+후처리 모델 동시 로딩 OOM,
   (b) 후처리가 final 을 막음. 진단: `AST-SEND` 카운트 0 이면 (b), `EngineDeadError` 면 (a).
4. **commit 은 주기가 아니라 스위치** — 생성 시작 트리거이고, 이미 돌고 있으면 무시된다.
   끝은 `final: true` 로 알린다. "이 모델은 증분이 아니다"라고 적기 전에 클라이언트를 의심할 것.
5. **지연 지표 정의 불일치** — 무음 크레딧, 서버측/클라이언트측 혼용.
6. **20클립 서브셋** — 같은 정렬 50클립과 CER 이 2배 차이 난다. 서브셋으로 비교하지 말 것.
7. **입력 레벨** — 클립 레벨이 50dB 벌어진 데이터셋에서 한 백엔드만 저레벨에서 전사가 빈다.
   레벨은 백엔드 특성이 아니라 **입력 조건**으로 취급하고 통일한다.
8. **증분 출력의 단어 경계** — 델타를 마지막 공백까지만 내보낸다. 안 하면 en WER 두 배.
9. **자체 지연 지표** — "오디오 끝" 기준은 시스템이 아니라 클립 길이를 잰다. 표준 LAAL 사용.
10. **언어 힌트** — 지정 수단이 없는 백엔드가 있으면 전부 안 준다.
11. **모델 기본값** — 문서·기억이 아니라 `config.json` 에서 확인. "기본값 비교"가 한쪽에만
    예산을 더 준 비교가 되기 쉽다.
12. **출력 채널 누락** — 미확정 가설을 따로 보내는 백엔드에서 확정 메시지만 세면 그 백엔드만
    지연이 5배로 나온다. **가장 비쌌던 함정.**
13. **숫자 표기(ITN)** — 말로 쓰는 백엔드는 인식이 맞아도 오답 처리된다. 정규화해서 값에 반영.

## 고칠 때의 구분

- **재측정이 필요한 것** — 측정 자체가 틀렸을 때(채널 누락, 조건 불일치, 지표 정의).
- **재채점으로 되는 것** — 전사는 정상이고 채점 규칙만 틀렸을 때(숫자 표기, 정규화).
  전사가 JSON 에 남아 있으므로 GPU 를 다시 쓰지 않는다.

둘을 섞어 말하면 필요 없는 런을 돌리게 된다.
