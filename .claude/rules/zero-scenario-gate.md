# zero 시나리오는 기준선과 같게 재현될 때만 올린다

`core/tests/zero_scenarios/` 에 시나리오를 새로 올리거나 기존 시나리오(yml·구간·기준선)를 고칠 때는, 커밋하기
전에 **지금 코드로 replay 해서 기준선과 같은 동작이 나오는지** 확인한다. GPU 때문에 글자 몇 개가 흔들리는 것은
괜찮다. 그보다 큰 차이가 나면 올리지 않는다.

```bash
python -m core.tests.zero_replay --gate <시나리오 이름 ...>
```

## 왜

시나리오는 "이 구간에서 이 문제가 났다"는 기록이고, 앞으로 코드를 바꿀 때마다 그 구간이 어떻게 바뀌는지 보는
기준점이다. 처음부터 기준선과 다르게 재현되는 시나리오는, 나중에 결과가 바뀌어도 코드 때문인지 시나리오 자체가
흔들려서인지 가를 수 없다.

GPU 흔들림은 막을 수 없다. 같은 음성·같은 코드로 replay 해도 vLLM 디코딩이 실행마다 똑같지 않아, 커밋 하나에서
`this excited` 와 `that excited` 처럼 단어가 바뀐 적이 있다(2026-11-27, scene5). 이것까지 막으면 아무것도 못 올린다.

## 같은 동작의 기준

`--gate` 가 기준선과 replay 의 커밋을 순서대로 짝지어 판정한다 (`core/tests/zero_replay.py` 의 `Replay.behavior`).

| 판정 | 뜻 | 올려도 되나 |
|---|---|---|
| `same` | 커밋이 글자까지 같다 | 된다 |
| `text-only` | 커밋 수, 각 커밋의 이유(seg·vad·lang·limit)·언어가 같고 시각이 0.15초 안이며, 글자만 조금 다르다(글자 유사도 0.8 이상) — GPU 흔들림 | 된다 |
| `different` | 커밋이 늘거나 줄었거나, 이유·언어·시각이 바뀌었거나, 글자가 크게 다르다 | 안 된다 |

## 지킬 것

- 시나리오에는 버전 필드를 채운다: `found_in`(찾은 bench 실행의 커밋), `introduced_in`(원인이 들어온 커밋과 무엇 때문인지,
  지켜야 할 동작이면 `guard`), 특정 설정에서만 생기는 문제면 `applies_when`. 뜻은 `core/tests/zero_scenarios/README.md` 의
  "버전 필드" 에 있다. 기능 때문에 생긴 문제면 그 기능을 켜는 설정을 `applies_when` 에 반드시 적는다 — 기능을 되돌렸을 때
  시나리오가 빠지는 근거가 이것이다(`git revert` 는 커밋을 이력에 남겨 커밋으로는 못 거른다).
- GPU 가 비어 있는지 본다. replay 는 12GB 쯤 쓰고, 다른 작업이 쓰고 있으면 종료 코드 3 으로 멈춘다. `--force-gpu` 는
  들어간다는 걸 알 때만 쓴다 — 남의 실험을 메모리 부족으로 떨어뜨릴 수 있다.
- 기준선(`fixtures/<이름>.jsonl`)이 있는 머신에서 돌린다. 기준선이 없으면 비교할 것이 없어 `--gate` 가 통과하지 않는다.
  기준선에는 데이터셋 원문이 들어 있으니 git 에도 S3 에도 올리지 않는다.
- 코드에 커밋 안 된 수정이 없는 상태(새 yml 제외)에서 돌린다. 기준선을 만든 bench 실행과 지금 코드가 같아야 비교가 된다.
- 고른 이름이 없거나, 모두 해당 없음으로 건너뛰어 replay 된 시나리오가 없으면 `--gate` 는 실패한다. 통과는 실제로
  replay 해서 같은 동작이 나온 것만 뜻한다.
- `different` 가 나오면 올리지 않고 원인을 가린다.
  - 기준선을 만든 bench 실행이 지금과 다른 코드에서 돌았다 — 지금 코드로 bench 를 다시 돌리고 `zero_cut cut` 으로 다시 자른다.
  - 구간 경계가 문제다 — `--from`·`--to` 를 바꿔 같은 이름으로 다시 자른다(구간은 VAD flush 자리로 맞춰진다). yml 의
    구간도 함께 바뀌니 `--gate` 를 다시 돌린다.
  - bench 를 다시 돌려야 하는데 커밋 안 한 새 yml 이 있으면, yml 을 잠시 `core/` 밖으로 옮긴다(bench 는 `core/` 아래
    커밋 안 된 파일이 있으면 돌지 않는다).
- 커밋 메시지에 replay 끝에 찍히는 `--gate:` 줄들(시나리오 이름·판정·설정)을 붙인다. 기준선과 replay 기록은
  로컬에만 남으므로, 다른 사람은 이 줄로 확인한 것을 안다.
- **데이터셋 원문은 꼭 필요한 짧은 구절만 쓴다.** yml(`what`·`why`·검사 글자)과 커밋 메시지에는 검사에 필요한 두세 단어
  구절만 옮긴다. 문장을 통째로 옮기지 않는다. replay·`zero_cut` 출력에는 원문이 나오니 그대로 붙이지 않는다. 기준선과
  replay 기록은 원문이 들어 있어 git 에도 S3 에도 올리지 않는다.
- 이 규칙은 시나리오를 올릴 때의 것이다. zero **코드**를 고칠 때는 동작을 바꾸는 게 목적이므로 `--gate` 가 아니라
  `checks` 통과와 `known_issues` 의 변화(`FIXED`)를 본다. 기준선은 문제가 보고된 때의 기록이라 고치지 않는다.
