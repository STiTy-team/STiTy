# zero 시나리오는 기준선과 같게 재현될 때만 올린다

`core/tests/zero_scenarios/` 에 시나리오를 새로 올리거나 기존 시나리오(yml·구간·기준선)를 고칠 때는, 커밋하기
전에 **지금 코드로 replay 해서 기준선과 같은 동작이 나오는지** 확인한다. GPU 때문에 글자 몇 개가 흔들리는 것은
괜찮다. 그보다 큰 차이가 나면 올리지 않는다.

```bash
python -m core.tests.zero_replay --gate <시나리오 이름 ...>
```

## 왜

시나리오는 "이 구간에서 이 문제가 났다"는 기록이고, 앞으로 코드를 바꿀 때마다 그 구간이 어떻게 바뀌는지 보는
기준점이다. 처음부터 기준선과 다르게 재현되는 시나리오는, 나중에 결과가 바뀌어도 코드 때문인지 시나리오 자체가
흔들려서인지 가를 수 없다.

GPU 흔들림은 막을 수 없다. 같은 음성·같은 코드로 replay 해도 vLLM 디코딩이 실행마다 똑같지 않아, 커밋 하나에서
`this excited` 와 `that excited` 처럼 단어가 바뀐 적이 있다(2026-11-27, scene5). 이것까지 막으면 아무것도 못 올린다.

## 같은 동작의 기준

`--gate` 가 기준선과 replay 의 커밋을 순서대로 짝지어 판정한다 (`core/tests/zero_replay.py` 의 `Replay.behavior`).

| 판정 | 뜻 | 올려도 되나 |
|---|---|---|
| `same` | 커밋이 글자까지 같다 | 된다 |
| `text-only` | 커밋 수, 각 커밋의 이유(seg·vad·limit)·언어·시각(0.1초 단위)이 모두 같고, 글자만 조금 다르다(글자 유사도 0.8 이상) — GPU 흔들림 | 된다 |
| `different` | 커밋이 늘거나 줄었거나, 이유·언어·시각이 바뀌었거나, 글자가 크게 다르다 | 안 된다 |

## 지킬 것

- 코드에 커밋 안 된 수정이 없는 상태(새 yml 제외)에서 돌린다. 기준선을 만든 bench 실행과 지금 코드가 같아야 비교가 된다.
- `different` 가 나오면 올리지 않고 원인을 가린다.
  - 기준선을 만든 bench 실행이 지금과 다른 코드에서 돌았다 — 지금 코드로 bench 를 다시 돌리고 `zero_cut cut` 으로 다시 자른다.
  - 구간 경계가 문제다 — `--from`·`--to` 를 바꿔 다시 자른다(구간은 VAD flush 자리로 맞춰진다).
- 커밋 메시지에 `--gate` 결과 줄(시나리오마다 `behavior vs baseline: same|text-only`)을 붙인다. 기준선과 replay 기록은
  로컬에만 남으므로, 다른 사람은 이 줄로 확인한 것을 안다.
- 이 규칙은 시나리오를 올릴 때의 것이다. zero **코드**를 고칠 때는 동작을 바꾸는 게 목적이므로 `--gate` 가 아니라
  `checks` 통과와 `known_issues` 의 변화(`FIXED`)를 본다. 기준선은 문제가 보고된 때의 기록이라 고치지 않는다.
