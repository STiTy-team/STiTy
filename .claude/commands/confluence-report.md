업무 공유 문서를 Confluence STiTy 스페이스에 만들어줘.

제목은 `[n차][세분화 업무명] 공유 문서`. 문서는 `문서 정리 > <n차 폴더>` 아래에서 **사용자가
고른 폴더**에 들어간다. 구분은 라벨(`공유`, `n차`)로 한다.

**형식을 외워서 쓰지 말 것.** 항목 구성은 [업무 공유 작성 가이드](https://stity.atlassian.net/wiki/spaces/STiTy/pages/327683)
에서 매번 읽어온다. 이 스킬의 절차나 서술 규칙을 바꾸면 가이드의 안내 문구도 같이 맞춰줘.

**올리기 전에 사용자 검토 1회는 반드시 거친다** (5절). 건너뛰지 말 것.

## 1. 현재 형식 확인 (항상 먼저)

```bash
PYTHONIOENCODING=utf-8 python .claude/confluence/confluence_doc.py --show-format
```

출력된 항목 이름을 그대로 `fields` 키로 쓴다. 지금은 표 칸 `업무 완료 일자`·`작성자` 와
줄글 항목 `한 줄 요약`·`결론`·`왜 이 작업을 했나?`·`업무 내용 정리` 다. 가이드가 바뀌면 달라지니 **출력된 것을 믿을 것.**

## 2. 차수·업무명·폴더 정하기

**폴더는 차수를 받은 뒤에 따로 묻는다.** 폴더 선택지는 차수에 따라 달라지므로, 차수와 폴더를
한 번에 물으면 틀린 목록을 보여주게 된다. 차수·업무명을 먼저 받고, 폴더 트리를 조회한 다음
폴더를 묻는다.

1. **차수(`round`)** 를 사용자에게 묻는다. 숫자만.
2. **세분화 업무명(`task`)** 을 사용자에게 입력받는다. 제목 둘째 칸에 그대로 들어간다.
   세션 작업에서 짐작해 채우지 말고, 후보를 제안하더라도 사용자가 정한 문구를 쓴다.
   1·2 는 한 번에 물어도 된다.
3. 답을 받은 뒤, 그 차수의 폴더 트리를 본다:

   ```bash
   PYTHONIOENCODING=utf-8 python .claude/confluence/confluence_doc.py --list-folders <n>
   ```

   차수 폴더 이름은 차수마다 다르다(`2차 업무 분담`, `3,4차 업무 분담`, `5차 업무 공유`).
   스크립트는 이름 앞의 차수 숫자로 찾는다. 출력된 하위 폴더를 선택지로 보여주고 어디에
   둘지 사용자에게 입력받는다. 고른 폴더의 id 가 `folder_id` 다.
   - 새 하위 폴더가 필요하면 부모 폴더 id 를 `folder_id` 에, 새 이름을 `new_folder` 에 넣는다.
     올릴 때 만들어진다.
   - 차수 폴더 자체가 없으면 스크립트가 차수 폴더 목록을 대신 보여준다. 멈추고 사용자에게 알린다.

## 3. 초안 항목 고르기

이 세션에서 실제로 한 작업을 근거로 쓴다. 추측해서 채우지 말 것. 수치는 **실제로 측정한 값만**.

본문을 쓰기 전에 `업무 내용 정리` 에 넣을 **항목 후보를 요약해서** 보여준다 — 소제목 하나에
한 줄 요약씩. 그리고 AskUserQuestion(`multiSelect: true`)으로 **빼도 되는 항목**을 고르게 한다.
후보가 4개를 넘으면 나눠서 묻거나, 목록을 먼저 텍스트로 보여주고 번호로 빼달라고 한다.

빠진 항목은 본문에서도, 결론에서도 다루지 않는다.

## 4. JSON 만들기

### 서술은 쉬운 말로 — `.claude/rules/plain-language.md` 를 그대로 적용한다

읽는 사람은 팀원이다. 파이프라인은 알지만 이 업무는 모른다. 그 사람이 한 번 읽고 넘어가게 쓴다.

- **한 문장에 한 가지.** 20자 안팎의 짧은 문장. 쉼표로 두 가지를 잇지 않는다.
- **소제목 아래 첫 문장이 결론.** 근거와 수치는 그 뒤에.
- **팀이 이미 아는 용어는 풀이하지 않는다.** VAD, 디코딩, ASR, partial/final, `<SEG>`,
  슬롯, whisper, COMET 같은 것에 괄호 설명을 달면 오히려 읽기 거슬린다. 풀이는 **이 업무에서
  새로 생긴 것**에만 — 새 방법, 새 지표, 새 이름. 그것도 처음 한 번, 문장으로.
- **코드 안의 이름(함수·플래그·파일)은 그대로 쓴다.** 무슨 일을 하는지는 그 이름이 처음 나오는
  문장이 말해 주면 된다.
- **숫자는 표로, 본문에는 그 표가 말하는 결론 한 줄.**
- **깊이는 줄이지 않는다.** 쉽게 쓰라는 것이지 얕게 쓰라는 게 아니다.

### `한 줄 요약` — 1~2줄

무엇을 바꿨고 결과가 무엇인지만. `text` 한 문단. 세부는 전부 결론으로 미룬다.

### `결론` — 요약에서 못 다 한 결론, 2~3문단 안

요약 바로 다음에 온다. 요약이 한 줄로 뭉뚱그린 것을 구체적으로 푼다 — 무엇이 확인됐고,
그래서 무엇을 하기로 했는지. **과정은 쓰지 않는다**(그건 업무 내용 정리의 몫). `markdown` 으로 쓴다.

**결론은 번호 목록(`1.` `2.` `3.`)으로 쓴다.** 결론 하나가 번호 하나다. 2~3개, 많아도 4개.
번호가 있어야 회의나 댓글에서 "결론 2" 처럼 가리킬 수 있다.

각 번호는 두 줄이다.

1. **첫 줄은 결론 한 문장 자체를 링크로.** 업무 내용 정리에서 그 결론의 근거가 있는 소제목으로
   건다. 문법은 `[보이는 글](#번호)` — `#1.2` 는 `## 1.2 …` 소제목으로 바로 내려간다.
2. **다음 줄은 네 칸 들여 써서 구체적인 내용.** 한두 문장. 들여 쓴 줄은 같은 번호 항목 안의
   다음 줄로 들어간다. **이 줄에는 링크를 달지 않는다** — 링크는 결론마다 첫 줄의 하나뿐이다.

```
1. [전사 품질은 그대로 두고 지연만 0.4초 줄였다](#2.1)
    WER 은 0.1%p 안에서 같았고 FSL 평균이 1.30초에서 0.88초가 됐다.
2. [기본값은 바꾸지 않고 플래그로 둔다](#3)
    한국어는 아직 재지 않았다.
```

링크 대상은 **번호로 시작하는 소제목**만 된다. 짝이 없는 링크가 있으면 스크립트가 멈추고
있는 앵커 목록을 보여준다. 연결되는 본문이 없는 결론에는 링크를 달지 않는다.

### `왜 이 작업을 했나?` — 계기와 의도, 2~3문장

결론 다음, 업무 내용 정리 앞에 온다. 무엇이 문제였고, 이 작업으로 무엇을 알거나 정하려 했는지만
쓴다. 읽는 사람이 업무 내용 정리를 읽기 전에 무엇을 보려던 작업인지 잡게 하는 자리다.
`text` 한 문단. 방법·조건·결과는 쓰지 않는다 — 그건 업무 내용 정리의 몫이다.
업무 내용 정리에는 배경 절을 따로 두지 않는다. 이 항목과 겹치기 때문이다.

### `업무 내용 정리` — `markdown`, 번호 붙은 소제목

- 큰 갈래는 `# 1. …`, 그 안은 `## 1.1 …`. 결론이 이 번호로 링크를 걸기 때문에 **번호는 필수.**
- 갈래는 한 일 / 결과 / 남은 것처럼 실제 업무 흐름에 맞게 정한다. 정해진 이름은 없다.
- 한 소제목 아래 문단이 셋을 넘으면 갈래를 더 나눈다.
- md 의 `#` 은 가이드 절 제목(h2) 바로 아래(h3), `##` 은 그 아래(h4)로 그려진다.

지원하는 md 문법 (`value` 는 md 문자열 하나, 줄바꿈은 `\n`):

| 문법 | 결과 |
|---|---|
| `# 1. 소제목` | 소제목 + 번호 앵커 (`#` 이 깊을수록 아래 단계) |
| `- 항목` / `1. 항목` | 글머리 / 번호 목록. 두 칸 들여쓰면 중첩된다. 표식 없이 들여 쓴 줄은 위 항목 안의 다음 줄 |
| `\| a \| b \|` + `\|---\|---\|` | 표 |
| `` `코드` ``, `**굵게**` | 인라인 코드, 굵게 |
| `[글](#1.2)` / `[글](https://…)` | 문서 안 링크 / 외부 링크 |
| ` ```python ` … ` ``` ` | 코드 블록 |

## 5. 전문 검토 (필수)

```bash
PYTHONIOENCODING=utf-8 python .claude/confluence/confluence_doc.py --json <경로>/report.json --dry-run
```

dry-run 은 제목·폴더 경로·라벨·각 항목 전문을 출력하고, 문서 안 링크가 모두 짝이 맞는지 확인한다.
**출력된 전문을 줄이지 말고 그대로 사용자에게 보여준 뒤** 올려도 되는지 묻는다.

- 고칠 점이 나오면 JSON 을 고치고 dry-run 을 다시 돌려 **바뀐 전문을 다시 보여준다.**
- 사용자가 승인하기 전에는 올리지 않는다.

## 6. 올리기

```bash
PYTHONIOENCODING=utf-8 python .claude/confluence/confluence_doc.py --json <경로>/report.json
```

- 같은 제목이 이미 있으면 `[n차][업무명][2] 공유 문서` 처럼 번호를 붙여 새 문서로 만든다
  (`seq` 로 직접 지정, `--no-autonumber` 로 끔). 기존 문서를 고치려면 `--update`.
- `folder_id` 가 그 차수 폴더 아래에 없으면 멈춘다. 다른 차수에 잘못 넣는 것을 막기 위해서다.

### 소유자

스크립트는 관리 계정(스티티)으로 올린다. 올린 뒤 `작성자` 칸의 이름과 **표시 이름이 정확히 같은**
Atlassian 계정이 하나 있으면 그 사람을 소유자로 바꾼다. 안 맞으면 알려만 주므로 `작성자` 는
Confluence 표시 이름 그대로 적는다.
