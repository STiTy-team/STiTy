# 스트리밍 ASR 백엔드 추가 — 플레이북

새 모델을 비교군으로 붙이고 기존 백엔드와 같은 축에서 재려 할 때 읽는 문서다.
Voxtral Mini 4B Realtime 과 Nemotron 3.5 ASR Streaming 0.6B 를 붙이면서 실제로 걸린
것만 적었다. 수치와 재현 절차는 `REPORT.md`, 실행 스크립트는 이 디렉터리에 있다.

**이 작업에서 결론을 뒤집은 건 모델이 아니라 전부 측정이었다 — 열세 번.** 그래서 이
문서는 "어떻게 붙이나"보다 **"무엇을 확인하지 않으면 틀린 숫자가 나오나"** 에 지면을 쓴다.

---

## 0. 30초 요약 — 이것만은

| 확인 | 안 하면 |
|---|---|
| 그 백엔드의 **출력 채널이 몇 개인가**(확정/미확정) | 한 백엔드만 다른 것을 재서 지연이 5배로 나온다 |
| **모델 기본값**을 config 에서 직접 확인 | "기본값 비교"가 한쪽에만 지연 예산을 3.5배 준 비교가 된다 |
| **언어 힌트**를 줄 수 있는 백엔드가 어디인가 | 한쪽만 힌트를 받은 채 정확도를 견준다 |
| **입력 레벨**을 통일 | 저레벨 클립에서 한 백엔드만 빈 전사를 낸다 |
| **숫자 표기** 규칙 | 인식이 맞아도 오답 처리돼 오류율이 2%p 부푼다 |
| 같은 클립·같은 개수 | 20클립 서브셋은 CER 이 2배로 흔들린다 |

## 1. 후보 심사

두 조건을 먼저 본다. **한국어를 하는가**, **네이티브 스트리밍인가.**

- 오프라인 모델을 청킹으로 감싸 넣으면 측정되는 건 모델이 아니라 **우리 커밋 정책**이다.
  기준선(Qwen3)이 이미 그 구조이므로 교란요인만 하나 더 는다.
- 라이선스는 통념이 반대일 수 있다. **CC-BY-4.0 에는 특허 그랜트가 없고**(본문에 명시),
  OpenMDW-1.1 은 copyright·patent·database·trade secret 전부에 무제한 권리를 준다.
  상업 배포를 볼 거면 CC-BY 쪽을 확인해야 한다.

초기 후보 다섯 중 셋이 한국어를 못 했고 둘은 스트리밍이 아니었다. 실제로 남은 건 둘이다.

## 2. 구현 단계

### 단계 1. env 를 나눈다 — 합치려 하지 말 것

의존성이 공존 불가다(`stity` transformers 4.57.6 / Nemotron ≥5.13.0 / Voxtral vllm ≥0.20.0).
그러나 **평가 하네스가 WebSocket 으로만 붙으므로 이건 장애물이 아니라 전제**다.

- `protocol.py` 는 vllm/transformers 를 **import 하지 않는다.** 엔진은 지연 import.
- 서버가 어느 env 에서 돌든 클라이언트는 모른다. 이 경계를 깨는 순간 env 분리가 무너진다.

### 단계 2. 프로토콜을 먼저 프로브한다

문서 대신 **소스와 실제 이벤트**를 본다. 눈 감고 브리지를 쓰지 말고 스키마를 덤프한 뒤
왕복 한 번에 짠다(`probe_voxtral.py` 가 그 용도다).

Voxtral 에서 이렇게 확인한 것들:
- `session.update` 의 `model` 은 **최상위**여야 한다. `session` 안에 넣으면 거절당한다.
- 성공해도 확인 이벤트가 **안 온다**(무응답이 정상).
- `turn_detection` 은 **수락되지만 아무 동작도 하지 않는다**(거절 이벤트조차 없다).
- `input_audio_buffer.commit` 은 주기가 아니라 **생성 시작 스위치**다. 이미 돌고 있으면
  `"Generation already in progress, ignoring commit"` 으로 무시된다.
- 끝은 `{"final": true}` 로 알린다. 이걸 보내야 `transcription.done` 이 온다.

> **교훈**: "이 모델은 증분 스트리밍이 아니다" 라고 적기 전에 우리 클라이언트를 의심할 것.
> 두 번 다 우리 잘못이었다.

### 단계 3. 엔진 어댑터 — 정식 스트리밍 API 를 찾는다

**청크마다 `generate()` 를 부르는 건 거의 항상 틀린 답이다.** 매 호출이 encoder/decoder
캐시를 리셋해 청크 경계의 단어가 통째로 빠진다. 예외도 경고도 없어 **전사를 눈으로 보지
않으면 못 잡는다.**

```
청크별 generate  매입국 충격 신혼단계가 때문에 문화충격보다 빠르게 발생하 더 각심할 수
제너레이터 API   제입국 충격은 신혼 단계가 없기 때문에 문화충격보다 빠르게 발생하며
                 더 오래 지속하고 더 극심할 수 있습니다.
```

정답은 mel 청크를 내놓는 **제너레이터를 `input_features` 로 한 번** 넘기는 것이다.
푸시 기반 서버에서는 큐 백드 제너레이터 + 워커 스레드로 감싼다.

부수적으로 확인할 것:
- **청크 크기는 샘플이 아니라 mel 프레임 수**로 고정된다(`first = 1 + 8*right`,
  `subsequent = 8*(right+1)`). 프로세서가 주는 샘플 수가 1프레임 과다일 수 있다 —
  프레임 수에서 역산할 것(`(need-1)*160`).
- 노브의 **이름과 유효값**을 확인한다. Nemotron 은 `att_context_size` 가 아니라
  `num_lookahead_tokens` 이고 0/3/6/13 만 유효하다. 다른 값을 주면 **조용히 13 으로 떨어져
  다른 이름의 같은 결과**가 저장된다.
- `generate()` 반환형이 텐서가 아닐 수 있다(`...GenerateOutput.sequences`).

### 단계 4. 증분 출력 — 세 군데를 고쳐야 끝난다

`generate()` 는 스트림을 다 먹은 뒤 반환하지만 토큰은 그 전에 나온다. 베이스
`GenerationMixin._sample` 이 스텝마다 `streamer.put()` 을 부르므로(`generation/utils.py`)
**모델 코드에 "streamer" 문자열이 없어도** `super().generate()` 경로면 스트리머가 동작한다.

끼우고 나서 남는 함정 둘:

1. **단어 경계.** 소비자가 조각을 `" ".join` 으로 잇는다. 델타가 단어 중간에서 잘리면 그
   자리에 공백이 박힌다(`lag be hind`, `ma de`) → **en WER 0.0959 → 0.1892.**
   델타는 **마지막 공백까지만** 내보내고 꼬리 단어는 다음으로 미룬다.
2. **중복 출력.** `finish()` 에서 스트리밍 누적본과 최종본을 문자열 비교로 "조정"하면 안
   된다. 같은 greedy 결과인데 공백 처리만 달라(`strip` vs `lstrip`) 매번 어긋나 전사가 통째로
   한 번 더 붙는다(**CER 1.245**). **스트리머가 한 번도 안 불린 경우에만** 최종본으로 대체.

> **ko CER 은 두 버그 모두에서 거의 안 움직였다**(0.0925~0.0933). 조사·어미가 붙어 공백
> 오염에 둔감하다. **증분화를 한국어로만 검증하면 못 잡는다.**

### 단계 5. 서버 기동 인자

- **GPU 예산을 명시**한다. 기본값을 믿으면 다른 프로세스와 합쳐 카드를 넘긴다.
  vLLM 은 `--gpu-memory-utilization` + `--max-model-len` 둘 다 봐야 KV cache 예산이 잡힌다.
- **이 박스에 nvcc 가 없다.** flashinfer 의 top-k/top-p 샘플러가 JIT 로 CUDA 커널을 빌드하다
  EngineCore 를 죽인다. **`VLLM_USE_FLASHINFER_SAMPLER=0` 만** 끄면 되고 컴파일·CUDA 그래프는
  정상이다(`--enforce-eager` 로는 안 풀린다).
- **`conda` 는 셸 함수다.** `timeout conda run ...` 처럼 외부 명령 뒤에 두면 죽는다.
  `$HOME/miniforge3/bin/conda` 절대경로를 쓸 것. 비대화형 ssh 에는 PATH 에 없다.

### 단계 6. 무인 드라이버

사람이 없는 동안 도는 전제로 짠다.

- **probe 게이트** — 실패해도 원인을 JSON 으로 남기고 그 백엔드만 건너뛴다.
- **`trap EXIT` GPU 반납** — 중간에 죽어도 카드를 놓는다.
- **포트가 이미 점유면 붙지 않는다** — 남의 서버 결과를 우리 것으로 적지 않기 위해서다.
- 산출물은 워크트리 **밖**에 둔다(`~/bench-results/<타임스탬프>/`). 공용 체크아웃은
  `git clean` 으로 날아간 전력이 있다.

## 3. 평가 — 조건을 맞추는 일이 측정의 90%

### 3.1 먼저 세라: 그 백엔드의 출력 채널은 몇 개인가

**가장 비싼 함정이었다.** 클라이언트가 `type=="final"` 만 수집했는데, Qwen3 서버는 미확정
가설을 `partial` 로 계속 내보내고 있었다(최소 간격 0.12초, 클립당 8~9개). 즉 **이 백엔드만
"확정 시각"을, 나머지 둘은 "출력 시각"을** 재고 있었다 — 지연이 5배로 나왔다.

새 백엔드를 붙이면 **서버가 보내는 메시지 타입을 전부 찍어 보고** 시작할 것.

```
 2.05s partial  다
 4.13s partial  다름이 수직 간격은 15m이며 공사는.
11.53s final    다리 및 수직 간격은 15m이며 ... 2017년      <- 이것만 세고 있었다
```

- 지연은 **"그 단위가 화면에 처음 뜬 시각"** 으로 통일한다. 미확정 가설도 화면에 뜨면 센다.
- 대신 그 출력이 **수정되는지**는 성질로 따로 적는다(Qwen3 는 처음 뜬 글자의 15~67%가 바뀐다.
  RNN-T·append-only 델타는 안 바뀐다). 지연 수치에 섞지 말 것.

### 3.2 조건 통일 체크리스트

| 항목 | 규칙 | 근거 |
|---|---|---|
| 클립 | 같은 데이터셋·같은 file_id·같은 개수 | 20클립은 CER 0.0254 ↔ 0.0510 로 흔들린다 |
| 지연 노브 | **모델 기본값**. config 에서 직접 확인 | `default_num_lookahead_tokens` 가 3인데 13을 기본값이라 적고 있었다 |
| 언어 힌트 | 셋 다 `auto`. 한 곳이라도 못 주면 전부 안 준다 | Voxtral 은 지정 수단 자체가 없다 |
| 입력 레벨 | 클립별 피크 정규화(0.5) | FLEURS 는 클립 레벨이 50dB 벌어져 있고 Voxtral 은 피크 0.005 아래에서 전사가 통째로 빈다 |
| 뒤 무음 | **필요한 백엔드만**(VAD 가 있는 쪽만) | VAD 없는 백엔드엔 마지막 flush 만 늦추는 낭비다 |
| 번역 | ASR 만 잴 거면 끈다 | 파이프라인이 `VAD-FINISH → 번역 → final` 이라 번역이 늦으면 final 이 안 나간다 |

### 3.3 지연 지표

- 레포 표준 구현을 쓴다 — `evaluation/ast/metrics_ast.py` 의 `laal_for_utterance`.
  AST 서버가 final 에 실어 보내는 `decisionAudioSec` 이 그 d_i 다.
- **자체 지표를 만들지 말 것.** `ttfo`/`completion_lag` 처럼 "오디오 끝" 기준 지표는 발화 중
  출력하는 백엔드에서 **클립 길이를 재는 값**이 된다(길수록 좋아 보인다).
- 단위는 **en 단어 / ko 글자**. 한국어를 단어로 세면 |Y| 가 지나치게 작아진다.
- **조각이 단어 중간에서 끊기는 백엔드**(Voxtral 델타)는 누적 텍스트에서 **완성된 단어**에만
  시각을 붙인다. 조각을 그대로 세면 26조각 → 24단위(실제 19단어)로 |Y_hyp| 가 부풀어
  γ·τ 가 어긋나고 **그 백엔드만 LAAL 이 왜곡된다.**
- `rtf`(= 마지막 출력 도착 / 오디오 길이)는 **계산 여유를 재지 못한다.** 입력을 1배속으로
  흘리기 때문이다. "실시간을 따라잡았나"까지만 말할 것.

### 3.4 정확도 지표

- CER(ko) / WER(en), NFKC + 소문자화 + 문장부호 제거.
- **숫자 표기를 반드시 확인한다.** Nemotron 은 아라비아 숫자를 한 번도 출력하지 않는다
  (50클립 중 0건, "이천십일년"). 참조는 숫자를 쓰므로 인식이 맞아도 오답이 된다 —
  ko 0.1013 → **0.0785**, en 0.0993 → **0.0812** 차이다.
- 정규화는 `itn_rescore.py` 를 쓴다. **참조에 실제로 있는 숫자**에 대응하는 말 표기만
  되돌린다. 가설 전체에서 한글 수사를 찾으면 `데이`→`데2`, `사육`→`46` 오검출이 난다.
  한 글자 수사는 뒤에 단위·조사가 올 때만, 앞 글자가 수사면 더 긴 수의 일부로 본다.

### 3.5 측정 후 무결성 점검

돌려놓고 반드시 확인한다. 전부 원자료(JSON)로 가능하다.

| 점검 | 통과 기준 | 실제로 걸린 적 |
|---|---|---|
| 같은 클립을 봤나 | file_id 목록·총 오디오 길이 일치 | — |
| 첫 클립 워밍업 오염 | 클립1 지연이 중앙값 근처 | ready 대기 30초로는 모델 로딩 중 첫 클립이 빠져 49클립이 됐다 |
| 꼬리 잘림 | 가설/참조 길이비 중앙값 ≈ 1.000 | — |
| 재현성 | 같은 설정 두 런의 클립별 오류율 일치 | — |
| 빈 전사 | 0건. 있으면 원인 규명 전까지 표를 쓰지 말 것 | 입력 레벨(R7), 서버 OOM(R3) |
| 전사 육안 확인 | 20개쯤 눈으로 읽기 | 청크별 generate 의 단어 누락은 이걸로만 잡힌다 |

## 4. 증상 → 원인 색인

| 증상 | 먼저 볼 것 |
|---|---|
| 전 클립 빈 전사, 클라이언트는 `ConnectionClosedOK: 1000 (OK)` | 서버 OOM 으로 EngineCore 사망. **정상 종료로 보이는 게 함정** |
| 서버 로그엔 전사가 있는데 클라이언트 HYP 가 빔 | `grep -c AST-SEND server.log` 가 0 이면 번역이 final 을 막고 있다 |
| `KeyError: A` (`_slot()`/`stream_slots`) | 독립 버그가 아니라 엔진 사망의 2차 증상 |
| 특정 클립만 전사가 통째로 빔 | 입력 피크 확인(0.005 근처 임계) |
| en 만 오류율이 두 배 | 조각 조립의 공백 오염. ko 는 둔감해서 안 보인다 |
| 전사가 정확히 두 번 반복(CER ≈ 1.2) | `finish()` 의 누적본↔최종본 조정 로직 |
| 한 백엔드만 지연이 몇 배 | 출력 채널을 빼먹었는지부터(3.1) |
| 지연이 클립 길이에 비례 | "오디오 끝" 기준 자체 지표를 쓰고 있다 |
| 스윕했는데 두 설정의 결과가 완전히 동일 | 무효값이 조용히 기본값으로 떨어졌다 |

## 5. 결과를 적을 때

- **결과를 맨 앞에.** 그 다음 왜 했나 → 어떤 단계로 구현했나 → 어떻게 측정했고 왜 그렇게
  했나 → 결과 → 결과 분석.
- **우리가 저지른 실수를 절 제목으로 올리지 않는다.** 단계 서술 안에 한 줄로 남기거나
  부록으로 뺀다. 보고서의 요지는 모델 구현과 성능 평가다.
- 분석 절에는 **결과 분석**만 쓴다. "어댑터를 고치니 출력이 나온다"는 분석이 아니라 구현 기록.
- **실험을 다 끝내고 쓴다.** 측정이 또 바뀌면 문서를 두 번 쓰게 된다(세 번 그랬다).
