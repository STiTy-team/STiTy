# 1:1 일상 대화 번역 평가 메트릭 설계안

> 대상 시스템: 서로 다른 언어를 사용하는 두 화자의 1:1 일상 대화를 `음성 → ASR 전사 → 텍스트 번역` 순서로 처리하는 시스템  
> 범위: 번역 결과의 품질 평가. 음성을 직접 번역하는 end-to-end speech translation은 현재 범위에서 제외한다.

## 0. 개요

현재 벤치마크는 `core/utils/metrics`에 구현된 WER, CER, BLEU, LAAL 계열 지표와 언어 감지·라우팅·분절 관련 운영 지표를 사용한다. 이 지표들은 ASR 오류, 표면적인 번역 일치도, 지연 시간, 시스템 라우팅 문제를 재현 가능하게 진단하는 데 유용하다.

그러나 실제 1:1 대화에서 중요한 다음 품질은 충분히 측정하지 못한다.

- 원문의 의미가 왜곡·누락·추가 없이 전달되었는가
- 숫자, 이름, 장소, 시간, 전문용어 같은 핵심 정보가 정확한가
- 번역문이 실제 대화에서 자연스럽고 일관적인가
- 짧은 턴 전환에서 대명사, 생략, 화자 관계와 말투를 올바르게 해석했는가
- 불완전한 ASR 전사에도 번역 품질이 안정적인가
- 질문, 요청, 제안, 부정, 확신의 정도 등 발화자의 의도가 보존되었는가

따라서 기존 메트릭을 폐기하거나 하나의 새 종합 점수로 대체하지 않는다. 기존 운영 지표 위에 다음 여섯 품질 축을 추가하고, 각 축을 세 개의 상호 보완적인 메트릭으로 평가한다.

1. 의미 전달
2. 중요 정보 보존
3. 유창성
4. 맥락 이해
5. 저품질 ASR 전사에 대한 강건성
6. 발화자 의도 보존

각 메트릭은 원시 결과를 개별적으로 저장한다. 근거가 검증되기 전에는 여섯 축을 임의의 가중합으로 합치지 않는다. 자동 메트릭은 사람 평가를 대체하는 절대 기준이 아니라, 모델 비교와 오류 진단을 위한 수단으로 사용한다.

음성 원본의 억양, 강세, 어조, 쉼, 감정처럼 ASR 전사에서 소실되는 정보는 현재 평가 대상이 아니다. 향후 음성을 직접 입력하는 번역 모델을 비교할 때 별도의 audio-native 평가 트랙으로 추가한다.

## 1. 기존에 구현돼 있던 메트릭들

현재 공용 메트릭은 `core/utils/metrics`에 있으며 벤치마크에서 실제 사용 중이다.

### 1.1 ASR 품질

| 메트릭 | 의미 | 해석 및 용도 |
|---|---|---|
| `wer` | Word Error Rate | 빈 ASR 출력까지 포함한 전체 전사 오류율. 치환·삭제·삽입 오류를 단어 단위로 측정한다. |
| `wer_scored_only` | 과거 방식의 WER | 빈 ASR 출력을 제외하고 실제로 점수 계산이 가능한 출력만 평가한다. `wer`와 함께 보면 빈 출력의 영향을 분리할 수 있다. |
| `cer` | Character Error Rate | 문자 단위 전사 오류율. 단어 경계가 모호하거나 형태 변화가 많은 언어에서 WER를 보완한다. |

WER와 CER는 ASR 품질 지표이며 번역 품질 지표가 아니다. 올바른 의역도 표면 문자열이 다르면 오류로 처리하므로 최종 번역의 의미 품질을 판단하는 용도로 사용하지 않는다.

### 1.2 번역 품질과 라우팅

| 메트릭 | 의미 | 해석 및 용도 |
|---|---|---|
| `bleu` | 올바르게 라우팅된 번역만 평가한 BLEU | 언어 감지와 대상 언어 라우팅이 정상적으로 수행된 사례에 한해 번역의 n-gram 일치도를 측정한다. |
| `bleu_all` | 오라우팅을 포함한 BLEU | 실제 전체 시스템 결과를 평가한다. 번역 모델 오류와 라우팅 오류의 영향을 함께 반영한다. |
| 언어 감지 정확도 | 입력 언어를 올바르게 판별한 비율 | 번역 품질 저하가 언어 감지 실패에서 발생했는지 확인한다. |
| 번역 대상 라우팅 정확도 | 올바른 목표 언어 또는 번역 경로로 전달된 비율 | 번역 모델 자체 오류와 시스템 라우팅 오류를 분리한다. |
| 언어 감지·라우팅 혼동 행렬 | 실제 언어와 예측·라우팅 언어의 조합별 빈도 | 특정 언어쌍에서 반복되는 오라우팅 패턴을 찾는다. |

BLEU는 빠르고 재현 가능하지만, 자연스러운 의역, 문맥 의존성, 구어체, 중요 정보 오류를 충분히 반영하지 못한다. 따라서 계속 기록하되 새 품질 평가의 단독 기준으로 사용하지 않는다.

### 1.3 지연 시간

| 메트릭 | 의미 | 해석 및 용도 |
|---|---|---|
| `laal_ms` | 커밋 정책 기준 LAAL | 시스템이 번역을 확정하는 정책을 반영한 지연 시간이다. |
| `laal_ca_ms` | 실제 체감 지연을 반영한 LAAL | 계산·도착 시간을 포함해 사용자가 체감하는 지연에 가깝게 측정한다. |
| `laal_uncapped_ms` | 상한 없는 LAAL | 극단적으로 긴 지연을 숨기지 않는 감사·디버깅용 값이다. |
| 평균 FSL | 결과 도착 지연 | 첫 결과가 사용자에게 도착하기까지의 평균 시간을 나타낸다. |

번역 품질과 지연은 하나의 점수로 합치지 않는다. 모델 간 비교에서는 품질–지연 trade-off를 함께 보고한다.

### 1.4 분절과 커밋 동작

| 메트릭 | 의미 | 해석 및 용도 |
|---|---|---|
| 커밋 원인별 비율 | 각 세그먼트가 확정된 원인의 분포 | 침묵, 길이 제한, 명시적 종료 등 어떤 정책이 번역 확정을 유발했는지 분석한다. |
| 발화당 세그먼트 수 | 하나의 발화가 나뉜 세그먼트 개수 | 과도한 분절 또는 지나치게 긴 지연의 원인을 진단한다. |

### 1.5 사용할 수 없는 지표의 처리

계산에 필요한 참조 데이터나 시간 정보가 없으면 값을 `null`로 기록하지 않는다.

- 해당 메트릭 필드를 결과에서 생략한다.
- `unavailable`에 메트릭 이름과 계산하지 못한 이유를 기록한다.

새로 추가하는 메트릭도 같은 규칙을 따른다. 예를 들어 대화 문맥이 없는 샘플에는 맥락 메트릭을 계산하지 않고, `unavailable`에 `missing_conversation_context`와 같은 구조화된 이유를 남긴다.

## 2. 우리가 평가해야 할 6가지 항목

| 번호 | 평가 항목 | 핵심 질문 | 기존 메트릭으로 충분한가 |
|---:|---|---|---|
| 1 | 의미 전달 | 원 언어의 의미가 왜곡·누락·추가 없이 전달됐는가? | 아니요. BLEU는 의미가 같은 다른 표현에 취약하다. |
| 2 | 중요 정보 보존 | 숫자, 날짜, 인명, 지명, 전문용어가 정확히 전달됐는가? | 아니요. 전체 문장이 유사하면 국소적인 치명적 오류를 놓칠 수 있다. |
| 3 | 유창성 | 번역된 텍스트만 보았을 때 자연스럽고 일관된 구어체인가? | 아니요. BLEU는 자연스러움을 직접 측정하지 않는다. |
| 4 | 맥락 이해 | 앞선 턴을 이용해 대명사, 생략, 화자 관계와 말투를 올바르게 처리했는가? | 아니요. 현재 메트릭은 기본적으로 발화를 독립적으로 평가한다. |
| 5 | ASR 강건성 | 저품질 전사에서도 최종 번역 품질이 안정적으로 유지되는가? | 아니요. WER는 전사 오류율만 보여 주며 그 오류가 번역에 미친 영향을 직접 측정하지 않는다. |
| 6 | 발화자 의도 보존 | 긍정·부정, 질문·요청·제안, 확신과 추측의 정도가 보존됐는가? | 아니요. 일반적인 전체 품질 점수는 작은 의도 반전을 놓칠 수 있다. |

여섯 항목은 완전히 독립적이지 않다. 예를 들어 부정 표현의 반전은 의미 오류이면서 의도 오류이고, 인명 누락은 의미 오류이면서 중요 정보 오류다. 중복을 억지로 제거하지 않고, 동일 오류가 어떤 사용자 위험을 만드는지 각 축에서 명시적으로 기록한다.

## 3. 각 항목 세부

## 3.1 의미 전달

### 평가 목표

원문의 명제적 의미가 번역에서 보존됐는지 평가한다. 다음 오류를 포함한다.

- 의미 왜곡 또는 오역
- 핵심 내용의 누락
- 원문에 없는 내용의 추가·환각
- 주체와 객체의 뒤바뀜
- 조건·인과·시간 관계의 오류
- 일부 또는 전체 미번역

### 추천 메트릭 3종

| 메트릭 | 입력 | 출력 | 역할 |
|---|---|---|---|
| **XCOMET** | 원문, 후보 번역, 참조 번역 | 전체 품질 점수, 오류 span, 심각도 | 주 의미 품질 지표. 점수뿐 아니라 오류 위치와 심각도를 진단한다. |
| **MetricX-24** | 후보 번역, 참조 번역, 선택적으로 원문 | 회귀 기반 품질 점수 | XCOMET과 다른 모델 계열의 독립적인 교차 검증 지표로 사용한다. 일반적으로 낮을수록 좋다. |
| **chrF++** | 후보 번역, 참조 번역 | 문자·단어 n-gram F-score | 빠르고 결정론적인 표면 지표. BLEU보다 형태 변화와 토큰화 차이에 상대적으로 견고하다. |

### 필요한 데이터

- 원 언어 ASR 전사
- 시스템 후보 번역
- 사람 참조 번역 1개 이상
- 가능하면 자연스러운 구어체 참조와 의미 중심의 정규화 참조
- 발화 ID 및 언어쌍

### 요구사항 및 주의점

- XCOMET과 MetricX의 정확한 모델 체크포인트와 버전을 기록한다.
- learned metric이 지원하는 언어쌍인지 확인한다.
- corpus 평균뿐 아니라 발화별 점수와 오류 span을 저장한다.
- BLEU, chrF++, XCOMET, MetricX가 서로 다른 결론을 내는 사례를 별도 검토한다.
- 모델 학습이나 선택에 사용한 메트릭 하나만으로 최종 모델을 평가하지 않는다.
- 참조 번역이 없으면 reference-based 지표를 생략하고 `unavailable`에 이유를 기록한다.

## 3.2 중요 정보 보존

### 평가 목표

전체 문장이 대체로 자연스럽더라도 실제 대화에서 치명적일 수 있는 구체 정보를 정확히 전달했는지 평가한다.

평가 대상은 다음을 포함한다.

- 수량과 서수
- 날짜와 시간
- 금액과 통화
- 전화번호와 주소
- 인명, 지명, 기관명, 제품명
- 도메인 전문용어
- 측정 단위

### 추천 메트릭 3종

| 메트릭 | 입력 | 출력 | 역할 |
|---|---|---|---|
| **Normalized Value Accuracy** | 원문·참조의 중요 값과 후보 번역 | 유형별 정확도 | 숫자, 날짜, 시간, 금액, 단위를 의미 값으로 정규화한 뒤 정확성을 평가한다. |
| **Critical Span F1** | 정답 중요 span, 후보 번역의 중요 span | precision, recall, micro/macro F1 | 개체명과 전문용어의 보존·누락·추가를 평가한다. |
| **Critical Fact Error Rate** | 중요 정보가 있는 발화별 판정 | 중요 정보 오류가 하나 이상인 발화 비율 | 사용자 위험 관점의 hard gate다. 전체 평균이 가리는 치명적인 국소 오류를 검출한다. |

Critical Fact Error Rate는 다음과 같이 정의한다.

\[
\mathrm{CFER}
=
\frac{\text{중요 정보 오류가 하나 이상 있는 발화 수}}
{\text{중요 정보가 포함된 전체 발화 수}}
\]

### 필요한 데이터

- 원문과 참조 번역의 중요 정보 span 주석
- 중요 정보 유형: `number`, `date`, `time`, `money`, `person`, `location`, `organization`, `product`, `term`, `unit` 등
- 정규화된 canonical value
- 허용 가능한 번역, 약어, 음역 및 표기 변형 목록
- 중요도 또는 심각도: 일반, 중요, 치명적
- 후보 번역에서 추출된 중요 span 및 원문 span과의 정렬 정보

### 요구사항 및 주의점

- 문자열 exact match만 사용하지 않는다. `오후 세 시`, `3 PM`, `15:00`처럼 같은 값을 나타내는 표현을 정규화해야 한다.
- 단위 변환은 값과 단위를 함께 비교한다. 정확한 환산은 정답으로 인정하고, 숫자만 같은 잘못된 단위는 오답으로 처리한다.
- 인명과 지명은 번역, 음역, 원어 유지 등 복수의 유효 표현을 허용해야 한다.
- 자동 NER 결과를 정답으로 간주하지 않는다. 평가셋에는 사람 검수된 중요 span 또는 신뢰할 수 있는 구조화 주석이 필요하다.
- precision과 recall을 모두 기록한다. recall만 보면 원문에 없는 개체를 추가하는 오류를 놓칠 수 있다.
- 전문용어는 용어집의 단일 표기만 강제하지 말고 문맥상 허용 가능한 변이를 관리한다.

## 3.3 유창성

### 평가 목표

의미 정확성과 분리하여, 번역 결과만 읽었을 때 목표 언어의 실제 일상 대화로서 자연스럽고 일관적인지 평가한다.

유창성은 다음 두 수준으로 나눈다.

- **턴 내부 자연스러움:** 문법, 어순, 어휘 선택, 번역투, 불필요한 반복
- **턴 간 스타일 일관성:** 존댓말, 호칭, 격식, 구어체 수준, 말투의 변화

### 추천 메트릭 3종

| 메트릭 | 입력 | 출력 | 역할 |
|---|---|---|---|
| **Spoken Fluency Judge Score** | 후보 번역, 선택적으로 목표 언어의 앞선 번역 턴 | 고정 rubric의 1~5점 및 사유 | 실제 일상 구어체의 자연스러움을 직접 평가한다. |
| **MQM Fluency/Style Error Rate** | 후보 번역과 오류 span 주석 | 심각도 가중 오류 수 또는 토큰당 오류율 | 문법, 어순, 번역투, 말투 불일치의 위치와 원인을 제공한다. |
| **Target-LM Pseudo-Perplexity** | 목표 언어 후보 번역 | 문장 또는 대화창별 pseudo-perplexity | 저비용 자동 보조 지표. 목표 언어에서 표현이 얼마나 전형적인지 측정한다. |

MQM 기반 오류율의 예시는 다음과 같다.

\[
\mathrm{FluencyErrorRate}
=
\frac{\sum \text{severity-weighted fluency errors}}
{\text{후보 번역의 목표 언어 토큰 수}}
\]

### 필요한 데이터

- 후보 번역 원문 그대로의 텍스트
- 대화 ID, 턴 순서, 화자 ID
- 턴 간 일관성을 평가할 경우 앞선 2~3개의 목표 언어 번역 턴
- 사람 평가용 유창성 rubric과 예시
- 목표 언어를 충분히 지원하는 고정 언어 모델
- MQM 평가 시 오류 span, 오류 유형, 심각도 주석

### 요구사항 및 주의점

- 의미 충실성과 유창성을 같은 프롬프트에서 한 점수로 평가하지 않는다.
- Spoken Fluency Judge에는 원문과 참조를 기본적으로 숨겨 의미 정확성이 유창성 판단에 섞이지 않게 한다.
- LLM judge의 모델 snapshot, 프롬프트, temperature와 실행 횟수를 고정·기록한다.
- pseudo-perplexity는 언어 모델과 토큰화 방식에 크게 의존하므로 서로 다른 언어 간 절대값을 비교하지 않는다.
- 매우 자연스럽지만 의미가 틀린 번역도 좋은 유창성 점수를 받을 수 있다. 의미 전달 지표와 항상 함께 본다.
- 원문의 필러, 반복, 말 더듬기, 자기수정을 무조건 그대로 옮기도록 요구하지 않는다. 의도적으로 보존해야 할 구어적 특징과 제거해도 되는 비유창성을 평가 가이드에서 구분한다.

## 3.4 맥락 이해

### 평가 목표

현재 턴만으로 결정할 수 없는 정보를 앞선 대화에서 올바르게 회수해 번역에 반영했는지 평가한다.

대표 현상은 다음과 같다.

- 대명사의 선행사
- 주어·목적어의 생략 복원
- 화자 구분과 지칭 대상
- 호칭, 존댓말, 격식과 화자 관계
- 동일 개체와 전문용어의 일관성
- 직전 질문에 대한 짧은 응답
- 정정과 자기수정
- 문맥을 이용한 중의성 해소

### 추천 메트릭 3종

| 메트릭 | 입력 | 출력 | 역할 |
|---|---|---|---|
| **Context-MQM** | 현재 원문·번역·참조와 앞선 이중언어 대화 문맥 | 문맥 조건 품질 점수와 오류 유형 | 기존 문맥 평가 방법론을 활용해 대화 문맥이 필요한 오류를 평가한다. |
| **Dialogue Inconsistency Rate** | 여러 턴의 원문과 후보 번역 | 문맥·화자·용어·말투 불일치가 있는 턴 비율 | MQM-Chat 계열 오류 체계로 대화 특화 불일치를 집계한다. |
| **Context Contrastive Accuracy** | 문맥과 올바른 후보·문맥 무시 오답 쌍 | 현상별 선택 정확도 | 모델이 실제로 문맥을 이용해야만 풀 수 있는 사례를 진단한다. |

### 필요한 데이터

- 대화 ID와 시간순 턴 ID
- 각 턴의 화자 ID
- 현재 턴과 앞선 2~3턴의 원문
- 현재 턴과 앞선 2~3턴의 후보 번역
- 가능하면 같은 범위의 참조 번역
- 대명사 선행사, 생략 요소, 화자 관계, 호칭, 격식 등 문맥 현상 label
- contrastive 평가용 정답 후보와 최소 하나의 통제된 오답 후보

### 요구사항 및 주의점

- 기본 문맥창은 앞선 2~3턴으로 시작하되 데이터로 적정 길이를 검증한다.
- 문맥을 제공한 점수와 현재 턴만 제공한 점수를 함께 저장해 문맥 효과를 분리한다.
- 전체 대화를 무조건 한 번에 입력하지 않는다. 긴 문맥은 무관 정보와 점수 희석을 유발할 수 있다.
- contrastive 오답은 문법적으로 자연스럽고 오직 목표 현상에서만 틀리게 만들어야 한다.
- 앞선 시스템 번역 자체가 틀린 경우와 현재 모델이 문맥을 잘못 이해한 경우를 구분할 수 있도록 원문 문맥도 보존한다.
- 참조 또는 문맥이 없는 샘플에는 지표를 계산하지 않고 `unavailable`에 이유를 기록한다.

## 3.5 저품질 ASR 전사에 대한 강건성

### 평가 목표

동일한 원 발화에 대해 깨끗한 전사와 저품질 ASR 전사를 입력했을 때 최종 번역의 품질이 얼마나 안정적으로 유지되는지 평가한다.

이 항목은 새로운 번역 품질 판정기라기보다 **paired evaluation protocol**이다. 의미 전달과 중요 정보 메트릭을 clean/noisy 조건에 동일하게 적용하고 변화량을 측정한다.

### 추천 메트릭 3종

| 메트릭 | 입력 | 출력 | 역할 |
|---|---|---|---|
| **ASR-induced Quality Drop** | clean/noisy 전사의 각 번역과 동일 참조 | 품질 지표별 절대·상대 하락량 | ASR 오류가 최종 번역 품질에 미친 직접적인 영향을 측정한다. |
| **Translation Invariance Score** | clean 전사 번역과 noisy 전사 번역 | 두 출력 간 의미 유사도 | 입력의 작은 손상에 대해 번역 결과가 얼마나 일관적인지 평가한다. |
| **Quality–Noise Degradation Slope** | 여러 WER·오류 강도 구간과 각 구간의 품질 | 회귀 기울기, AUC, worst-bucket score | 오류가 증가할 때 성능이 얼마나 빠르게 무너지는지 평가한다. |

ASR-induced Quality Drop은 품질 지표마다 별도로 계산한다.

\[
\Delta Q_{\mathrm{ASR}}
=
Q(h_{\mathrm{clean}})
-
Q(h_{\mathrm{noisy}})
\]

높을수록 좋은 지표에서는 값이 클수록 강건성이 낮다. MetricX나 오류율처럼 낮을수록 좋은 지표는 방향을 반대로 정규화해 보고한다.

### 필요한 데이터

- 동일 음성에 대한 사람 검수 clean 전사
- 실제 ASR 출력인 noisy 전사
- clean/noisy 전사를 각각 입력해 생성한 번역 결과
- 두 조건이 공유하는 참조 번역
- noisy 전사의 WER, CER 및 오류 정렬
- ASR 오류 유형 label: 치환, 삭제, 삽입, 숫자·개체 손상, 동음이의어, 구두점 소실, 문장 경계 오류 등
- 가능하면 서로 다른 소음·악센트·마이크·말속도 조건과 심각도

### 요구사항 및 주의점

- 실제 ASR 오류를 우선 사용하고 합성 노이즈는 부족한 오류 유형을 보충하는 용도로 사용한다.
- clean/noisy 번역은 동일한 번역 모델 설정과 decoding 조건으로 생성한다.
- Translation Invariance가 높아도 두 결과가 똑같이 틀릴 수 있으므로 Quality Drop과 함께 해석한다.
- 전체 WER가 같아도 중요 단어 하나가 손상된 경우와 조사·관사 오류가 많은 경우의 영향은 다르다. 오류 유형별 slice를 반드시 제공한다.
- 빈 ASR 출력은 제외하지 않는다. 별도 catastrophic failure로 기록하고 전체 운영 강건성 결과에 포함한다.
- 평균 외에 WER 구간별 품질, worst-group 결과와 신뢰구간을 기록한다.

## 3.6 발화자 의도 보존

### 평가 목표

문장의 대략적인 주제가 같더라도 실제 대화 행동과 태도를 바꾸는 오류를 탐지한다.

평가 대상은 다음을 포함한다.

- 긍정과 부정 및 부정 범위
- 질문, 정보 요청, 행동 요청, 명령, 제안, 확인, 동의, 거절
- 확실함, 가능성, 추측, 의무, 허용
- 조건과 가정
- 완곡함과 단호함
- 주저, 유보, 강조

### 추천 메트릭 3종

| 메트릭 | 입력 | 출력 | 역할 |
|---|---|---|---|
| **Polarity Preservation Accuracy** | 원문과 후보 번역의 polarity label | 정확도와 polarity reversal rate | 긍정·부정 및 의미 반전을 직접 평가한다. |
| **Speech-Act Macro-F1** | 원문과 후보 번역의 화행 label | 클래스별 precision/recall/F1과 macro-F1 | 질문·요청·명령·제안·확인·거절 등의 대화 기능을 평가한다. |
| **Modality/Stance Preservation Accuracy** | 원문과 후보 번역의 양태·태도 label | 정확도 또는 단계 간 거리 | 확신, 가능성, 추측, 의무, 허용의 강도가 보존됐는지 평가한다. |

### 필요한 데이터

- 원문과 참조 번역의 polarity label 및 부정 범위
- 원문과 참조 번역의 speech-act label
- modality/stance label과 강도 단계
- 후보 번역에서 같은 label을 얻기 위한 사람 주석, 고정 분류기 또는 구조화된 LLM 판정
- 중의적인 발화에 필요한 앞선 2~3턴의 대화 문맥
- 현상별 최소쌍 또는 contrastive 테스트 사례

권장 speech-act label의 초기 집합은 다음과 같다.

- `statement`
- `question`
- `information_request`
- `action_request`
- `command`
- `suggestion`
- `confirmation`
- `agreement`
- `rejection`
- `apology`
- `thanks`

권장 modality/stance 단계의 초기 집합은 다음과 같다.

- `certain`
- `probable`
- `possible`
- `speculative`
- `obligatory`
- `permitted`
- `hesitant_or_withheld`

### 요구사항 및 주의점

- 단순히 물음표나 부정어가 존재하는지 확인하지 않는다. 간접 요청과 부정 범위를 판정할 수 있어야 한다.
- 클래스 불균형이 크므로 speech-act는 accuracy보다 macro-F1을 우선한다.
- 한 발화가 질문이면서 요청인 것처럼 복수 화행을 가질 수 있다. 데이터에 따라 multi-label 평가를 허용한다.
- polarity reversal은 일반 오류보다 높은 심각도의 critical error로 별도 집계한다.
- modality는 완전 일치뿐 아니라 강도 차이도 기록한다. 예를 들어 `certain → possible`과 `certain → impossible`을 같은 오류로 취급하지 않는다.
- 자동 분류기나 LLM 판정은 사람 주석 파일럿셋과의 일치도를 먼저 검증한다.

## 4. 권장 결과 구조

각 실행에서는 종합 점수 하나 대신 다음 구조의 scorecard를 생성하는 것을 권장한다.

| 축 | 대표 지표 | 방향 |
|---|---|---:|
| 의미 전달 | XCOMET, MetricX-24, chrF++ | XCOMET·chrF++ ↑, MetricX ↓ |
| 중요 정보 | Normalized Value Accuracy, Critical Span F1, Critical Fact Error Rate | Accuracy·F1 ↑, Error Rate ↓ |
| 유창성 | Spoken Fluency Judge, MQM Fluency Error Rate, Pseudo-Perplexity | Judge ↑, Error Rate·PPL ↓ |
| 맥락 이해 | Context-MQM, Dialogue Inconsistency Rate, Context Contrastive Accuracy | Context-MQM·Accuracy ↑, Error Rate ↓ |
| ASR 강건성 | Quality Drop, Translation Invariance, Degradation Slope | Drop·하락 기울기 ↓, Invariance ↑ |
| 의도 보존 | Polarity Accuracy, Speech-Act Macro-F1, Modality Accuracy | 모두 ↑ |

모든 결과에는 다음 공통 metadata를 남긴다.

- 데이터셋 및 버전
- 언어쌍
- 모델과 decoding 설정
- 참조 번역 버전
- 메트릭 구현 버전 및 체크포인트
- 정규화 정책
- 문맥창 크기
- LLM judge 모델, 프롬프트 버전, temperature
- 샘플 수와 계산 제외 수
- `unavailable` 사유

최종 모델 선택에서는 전체 평균뿐 아니라 중요 정보, polarity reversal, 빈 출력, 오라우팅과 같은 critical failure를 먼저 hard gate로 확인한다. 그다음 의미·유창성·맥락·강건성의 개선과 품질–지연 trade-off를 함께 비교한다.
