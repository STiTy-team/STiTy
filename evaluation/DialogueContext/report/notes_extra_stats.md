## 요약

`scripts/extra_stats.py` 를 새로 만들어 돌렸고, 표 T8~T13(각각 csv+md, T10b 포함)과 그림 1개를 만들었습니다. 이 스크립트는 `aggregate.load_merged`, `to_markdown`, `SEED` 와 `figures.py` 의 스타일·팔레트를 import 해서 쓰고, 기존 스크립트는 고치지 않았습니다. 부트스트랩은 인스턴스 20개를 복원추출하고 1000회, 시드 20260925입니다. ALL 은 인스턴스마다 네 모델의 차이를 먼저 평균한 뒤 인스턴스를 복원추출한 값입니다. 신뢰구간 끝을 소수 셋째 자리로 반올림했을 때 0을 벗어나야 `*` 를 붙였습니다.

**핵심 결론:** 20개 인스턴스로 확실히 구분되는 것은 "문맥을 늘리면 좋아진다"는 것과 "단서가 창 안에 들어오는 순간 좋아진다"는 것 두 가지입니다. 전략끼리의 차이는 대부분 구분되지 않습니다. 지연도 n=0~5 사이에서는 측정할 만큼 늘지 않았습니다.

- **ALL, n=5 에서만:** SRC_TGT−SRC 가 judge +0.115 [0.012, 0.231], check +0.094 [0.025, 0.175]로 구분됩니다.

  - gpt-6-luna: SRC_TGT−SRC (judge +0.081, check +0.083)
  - gemma: SRC_TGT−SRC check +0.150, SPK_SRC_TGT−SRC_TGT judge +0.133

## 3. 단서 거리 (T10, T10b)
각 인스턴스의 note 와 대조했고, 받은 그룹 분류가 모두 맞아 바꾸지 않았습니다. 다만 부분 단서가 있는 인스턴스가 있습니다.

- c02-t07: 'mock-ups' 가 3턴 앞에 있습니다.
- c03-t12: '애들' 단서가 1턴 앞에 있습니다.
- c02-t12: 단서가 SRC 쪽에만 있습니다.
- c02-t15: trap 이라 n=0 에서도 통과합니다.

ALL 의 check pass 를 주어진 n(0 / 1 / 3 / 5)별로 보면 다음과 같습니다.

- **단서가 창에 들어오는 단계**의 이득은 세 그룹 모두 유의합니다: +0.427*, +0.420*, +0.338*. gemma 의 n=5 그룹(+0.35, 인스턴스 5개)만 예외입니다.

- **단서 전의 부분 창:** n=3 그룹에 n=1 을 주면 −0.078 로 오히려 조금 떨어집니다(qwen −0.19). 유의하지는 않지만, 가까운 방해 인물(c01-t14 의 택시 기사)이 들어오는 trap 과 방향이 맞습니다. n=5 그룹의 n3−NONE +0.175* 는 부분 단서 때문입니다.

## 4. 지연 (T11)
- **전체 지연은 입력 길이로 설명되지 않습니다.** 네 모델 모두 R² 가 0.000~0.005 입니다. 로컬 모델은 출력 길이를 함께 넣으면 R² 가 0.98 이 되고, 출력 토큰 하나에 약 19 ms 입니다. 입력 100토큰당 증가는 gemma 6.1 ms, qwen 4.0 ms 입니다.
- 로컬 모델의 TTFT 는 100토큰당 gemma 6.4 ms, qwen 4.5 ms 늘어납니다(R² 0.13, 0.11).
- GPT 와 DeepL 은 입력 길이와 지연 사이에 관계가 없습니다.
- **중앙값 차이 n5−NONE (95% CI):** DeepL −0.4 [−16, 12], gemma +8.6 [−61, 54], GPT −12.9 [−58, 28], qwen +0.1 [−44, 65]. 모두 구분되지 않습니다.
- **턴당 토큰 수(실측):** SRC_TGT 는 약 30~31 토큰으로 요청하신 ~60 의 절반입니다. 전략 합산은 약 25 토큰, DeepL 은 턴당 78자입니다.
- **외삽 (측정값이 아니라 직선을 연장한 추정):**
  - SRC_TGT 20턴(약 770토큰): 로컬 지연 +30 ms 안팎 (gemma 268→307, qwen 302→327), TTFT 37→77 ms
  - 50턴(약 1700토큰): gemma 365 ms, qwen 363 ms, TTFT 138 / 109 ms
  - 턴당 60토큰을 가정하면 50턴에서 gemma +185 ms, qwen +121 ms 정도입니다.
  - GPT 와 DeepL 은 기울기가 잡음 수준이라 외삽값에 의미가 없습니다.

## 5. GPU 경합 (T12)
- 시각 맞추기: started_at 은 UTC 이고, +9시간 해서 KST 로그와 맞췄습니다. 샘플은 76개이고 whole-GPU util 의 중앙값은 12% 입니다.
- 우리 로컬 작업이 도는 순간의 util 평균은 40.2%, 돌지 않는 순간은 16.0% 입니다. 따라서 util 에는 우리 작업 부하가 섞여 있습니다.
- **util 이 높을 때와 낮을 때의 중앙값 차이:** gemma +31 ms [−3, 64], qwen +22 ms [−11, 47].
- **처음 2분(샘플 없음)과 나머지의 차이:** gemma −28 ms [−49, 5], qwen −19 ms [−47, 22].
- **결론:** util 이 높을 때 20~30 ms 느린 경향만 있고, 신뢰구간이 0을 포함합니다. 경합이 로컬 지연을 뚜렷이 옮겼다고 볼 근거는 없습니다.
