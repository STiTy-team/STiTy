## 결론

gpt-6-sol 판정기는 믿을 만합니다. 제가 먼저 직접 매긴 판정과도, Gemini 판정기와도 거의 똑같이 판정했고, 자기 회사 모델(gpt-6-luna)을 더 좋게 보는 편향도 이번 표본에서는 보이지 않았습니다. 다만 register_politeness 와 discourse_connective 가 낮게 나온 데는 **체크 문구가 너무 엄격한 탓이 꽤 섞여 있습니다.** 그 부분은 판정기가 아니라 데이터 쪽 문제입니다.

## 1. 직접 판정한 것과 비교

**표본.** 시드 20260925 로 뽑은 40건입니다. 인스턴스 20개에서 2건씩 뽑았고, 모델마다 10건씩 돌아가게 했습니다. 이렇게 하면 태그 10개가 전부 들어갑니다. 판정기 결과를 보기 전에 체크 문구를 글자 그대로 적용해서 제가 먼저 통과/실패를 정했습니다.

**일치율.**
- 전체: 체크 72개 중 72개 일치(100%). 태그 10개 모두 100%입니다.
- 애매한 경우도 저와 같게 판정했습니다. 예를 들어 "Oh, so did he like it?" 은 성별 체크는 실패, 끌어들이면 안 되는 내용 체크(context_trap)는 통과로 판정했습니다.

**register_politeness·discourse_connective 는 해당 인스턴스 6개의 판정 173건을 모두 봤습니다.** 173건 중 169건(98%)이 일치했습니다. 어긋난 4건은 모두 c04-t12 입니다. "Okay, don't worry" 3건과 "Yeah, don't worry" 1건인데, 판정기는 이것들이 강한 긍정이 아니라며 실패를 줬습니다. 체크 문구 기준으로는 통과로 볼 수 있어서, 이 인스턴스에서만 판정기가 문구보다 조금 더 엄격합니다.

전체 데이터의 실제 통과율은 아래와 같습니다(전 행 기준). gpt-6-luna 의 register 통과율은 0.51 로, 모든 모델이 25% 이하라는 전제와 다릅니다.

| 태그 | DeepL | Gemma | Luna | Qwen |
|---|---|---|---|---|
| register_politeness | 0.02 | 0.00 | 0.51 | 0.22 |
| discourse_connective | 0.36 | 0.04 | 0.62 | 0.00 |

**인스턴스별 진단 — 무엇이 문제인가.**

| 인스턴스 | 원인 | 내용 |
|---|---|---|
| c01-t12 (그렇기는 한데) | **체크 문구** | "That's true, but I was still late" 를 문구가 대놓고 실패로 정해 뒀습니다. 그런데 한국어 원문 자체가 "그렇기는 한데" 로 먼저 인정하는 말이라, 이건 가장 직역에 가깝고 자연스러운 번역입니다. 60행 중 59행이 이 문구 하나 때문에 실패했습니다. |
| c02-t15 (근데 → "But") | 문구가 엄격함 | 말로 화제를 돌릴 때 "But" 을 쓰는 건 경계선입니다. Qwen 과 Gemma 는 대부분 이것만으로 실패했습니다. |
| c04-t12 (그럼 → "Then") | 실제 번역 오류 | Qwen·Gemma·DeepL 이 "Then/Well then" 으로 옮겼습니다. |
| c02-t12 (팀장님) | 문구가 엄격함 | 질문을 "you" 에게 하고 끝에 "…, Team Leader?" 하고 부르기만 해도 실패입니다. 제3자로 옮긴 경우("Is the team leader going?")만 진짜 오류이고, 그건 대명사 체크가 이미 잡습니다. |
| c03-t14 (어머님 → "Mom") | 실제 오류 | 판정기가 맞습니다. |
| c05-t14 | 대부분 실제 오류 | "brother" 류가 진짜 오류입니다. 다만 "Oppa, ask your mom…" (luna 15행 중 7행)은 문구 때문에만 실패했습니다. |

**문구를 완화하면 통과율이 이렇게 바뀝니다.** 완화 기준은 c01-t12 에서 "That's true, but" 허용, c02-t12 에서 호칭은 붙어도 질문이 "you" 에게 향하면 허용, c02-t15 에서 "But" 허용, "Oppa" 허용입니다(엄격 → 완화).
- register: DeepL 0.02→0.36, Gemma 0.00→0.09, Luna 0.51→0.91, Qwen 0.22→0.42
- connective: DeepL 0.36→0.69, Gemma 0.04→0.64, Luna 0.62→0.93, Qwen 0.00→0.67

그러니까 **Qwen 이 connective 에서 0% 인 것은 c04-t12 만 진짜 오류이고, 나머지 두 인스턴스는 문구 탓입니다.** 모델 순위는 완화해도 거의 그대로이지만, 절대 수치는 크게 달라집니다.

## 2. 다른 회사 판정기(Gemini)로 편향 확인

**설정.**
- 모델: `gemini-3.8-flash`. API 목록에서 정식 출시(GA) 모델 중 가장 최신이라 골랐습니다. 3.x 대 Pro 는 아직 preview 뿐이고, 정식 출시된 Pro 는 한 세대 전인 2.5 입니다.
- 프롬프트: judge_context.py 의 `SYSTEM_PROMPT` 와 `build_user_prompt` 를 그대로 가져다 썼습니다. JSON 출력, temperature 0.
- 표본: 앞의 40건에 40건을 더한 80건, 모델마다 20건입니다.

**결과.**
- 체크 일치율 97.9%(144개 중 141개), kappa 0.96. 통과율도 gpt 0.583, Gemini 0.576 으로 거의 같습니다.
- 앞의 40건에서 제 판정과 Gemini 도 97.2% 일치했습니다.
- judge_mean(여섯 항목 점수 평균): 두 판정기 순위 상관(Spearman) 0.93, 평균 차이 −0.004.
- 모델별 차이(gpt − Gemini): DeepL −0.075, Gemma +0.092, **Luna −0.025**, Qwen −0.008.
- 자기 선호 지표(luna 차이에서 다른 모델 차이를 뺀 값)는 −0.028 이고, 95% 신뢰구간(부트스트랩)은 [−0.14, +0.10] 입니다. **gpt-6-sol 이 luna 를 Gemini 보다 더 후하게 본다는 증거는 없습니다.** 모델 순위도 두 판정기가 같습니다(Luna > DeepL > Qwen > Gemma).
- 항목별로는 naturalness(순위 상관 0.61)와 register_consistency(0.66)에서 두 판정기가 가장 덜 일치합니다.

**비용.** Gemini 80회 호출에 $0.167 이 들었습니다. 단가는 입력 $0.75 / 출력 $3.75 (100만 토큰당, 2026년 말까지 프로모션 가격)이고, 예산 상한 $3 대비 여유가 많습니다. 호출마다 사용량과 누적 비용을 기록했습니다.

## 보고서에 적어야 할 한계

1. **register_politeness·discourse_connective 태그 점수의 상당 부분은 체크 문구 때문입니다.** 특히 c01-t12 는 자연스러운 직역을 실패로 정해 뒀습니다. 태그별 성공률 옆에 이 사실을 밝히거나, 완화 기준 수치를 함께 싣는 게 좋습니다.
2. **두 판정기가 잘 맞는다고 체크 문구가 옳다는 뜻은 아닙니다.** 두 판정기와 저 모두 같은 문구를 받았으니, 이번 교차 확인은 "판정기가 문구를 일관되게 적용하는가" 만 보여 줍니다.
3. **자기 선호 편향 확인은 표본이 작고, luna 점수가 거의 만점이라 검출력이 낮습니다.** 모델당 20건이고 luna 평균이 4.84~4.87 입니다. "없다" 가 아니라 "±0.1 점 수준에서 보이지 않았다" 로 적어야 합니다.
4. **Gemini 는 thinking 수준을 low 로 요청했지만 추론 토큰이 0 으로 보고됐습니다.** gpt-6-sol 의 reasoning low 와 조건이 완전히 같지는 않습니다.
5. **c04-t12 에서는 판정기가 문구보다 엄격합니다.** "Okay/Yeah" 를 실패로 봐서, connective 통과율이 조금 낮게 나옵니다.
