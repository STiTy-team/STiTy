# 방출 일정표 라벨 (prefix14) — 설계

작성 2026-11-11. 대상: zprobe-prefix 번역 어댑터의 다음 코퍼스 세대. 전 세대는 prefix13tr(번역만, 태그 없음, ASR 글 없음).

## 1. 왜

prefix13tr 은 온전히 나온 문장만 보면 COMET 0.784 로 역대 최고인데, 48문장 중 14문장이 잘려(출력이 정답의 60% 미만) 전체가 0.710 에 머문다. 잘림은 모델이 구 끝까지 기다리다가 발화가 리셋되는 순간(VAD 끝, LID 리셋, 길이 상한) 아직 안 낸 내용을 잃는 것이다. en→ko 지연(LongYAAL 2712ms)도 같은 뿌리다.

기다림은 라벨이 가르친 것이다. 지금 라벨은 "구 i 가 끝나면 무엇을 덧붙이나"만 있고 "언제부터 낼 수 있나"가 없어서, 구 중간 상태는 합성 규칙으로 메운다 — `wait_mid`(구 중간이면 무조건 빈 출력), `catchup`(밀린 구를 내라). 즉 구 안에서 먼저 낼 수 있는 내용도 구 끝까지 묶여 있다.

이 세대는 라벨을 **발화 하나의 방출 일정표**로 바꾼다: 들린 단어 수에 따라 무엇을 덧붙이는지를 라벨러가 직접 정한다. 모델은 "이 단어는 지금, 저 단어는 나중에"를 상황별로 배운다.

런타임 강제 방출(`stall_flush_sec`)은 쓰지 않는다. VAD 가 열린 무음 구간에서 환청을 만들어 팀이 폐기했다.

## 2. 목표·비목표

목표
- 잘림을 줄여 en→ko COMET 을 관문(ko 0.750 / LongYAAL 1990ms) 쪽으로 올린다. 온전한 문장의 품질(0.78)은 유지한다.
- 지연은 지금보다 나빠질 수 없게 라벨에서 보장한다(아래 마감 규칙).
- en 타깃(ko→en)의 재료를 10,000 발화로 늘린다. 관문 en 0.671 / 1360ms.

비목표
- 같은언어 전사 슬롯. 어댑터는 번역만 배운다. 라우터가 같은언어 슬롯을 버리는 일은 별도 작업.
- 소스 언어 태그, ASR 글 입력. 둘 다 없다(prefix13tr 그대로).
- 런타임 변경. 추론 코드는 그대로 두고 라벨·코퍼스만 바꾼다.

이러면 실패다
- 지연이 prefix13tr(2712 / 1867)보다 늘어난다.
- 못 들은 내용을 지어내는 조각이 늘어 COMET 이 올라도 믿을 수 없다. 그래서 지어냄 비율을 반드시 같이 잰다.

## 3. 라벨 형식

라벨러(LLM)는 발화 하나를 보고 **일정표**를 낸다: `(after_word, text)` 목록. `after_word` 는 원문 단어 번호(1부터, 공백 분리; 한국어는 어절, 일본어·중국어는 강제 정렬 단위)로, "이 단어까지 들리면 `text` 를 덧붙여라"는 뜻이다. 같은 `after_word` 에 항목이 여럿이어도 된다.

```
원문:  The manager | approved the budget for the new office | yesterday.
일정표: (2, "매니저가") (9, "새 사무실 예산을") (10, "어제 승인했어요")
```

라벨러에게 주는 것: 원문(단어 번호 붙여서), 참조 번역(있으면), 지금 구 경계(참고용). 발화당 호출 한 번.

### 3.1 라벨러가 지켜야 하는 규칙 (프롬프트에 그대로 적는다)

1. **듣기 전엔 못 낸다.** 항목 `(k, text)` 의 `text` 에는 단어 1..k 에서 알 수 있는 내용만 들어간다. 이름·숫자·부정·시제가 뒤에서 오면 그 단어까지 기다린다.
2. **낸 건 못 고친다.** 항목들을 순서대로 이어 붙인 것이 발화 전체의 온전한 번역이어야 한다. 앞 항목을 뒤에서 고쳐 쓰는 일은 없다.
3. **뜻이 확정된 조각은 즉시 낸다.** 명사구·장소·시간처럼 뒤에 무엇이 와도 안 바뀌는 조각은 들리는 즉시. 단, 그 자리에 내도 최종 문장이 자연스러워야 한다(어순은 라벨러가 발화 전체를 보고 맞춘다).
4. **뜻이 뒤에 달린 조각은 정하는 단어까지 미루되, 절 끝을 넘기지 않는다.** 동사·부정·의문·시제. "I don't think he's coming" 의 부정은 뒤 절에 걸리므로 그 절이 끝날 때 낸다.
5. **어떤 내용도 들린 구로부터 두 구 넘게 밀리지 않는다.** 지금 catchup 라벨이 전제하는 밀림(1~2구)과 같다. 이 상한이 "지연은 지금보다 나빠지지 않는다"의 근거다.
6. **빈 일정표 구간은 정당해야 한다.** 낼 수 있는데 안 낸 것은 지어냄만큼 나쁘다(현행 규칙 유지).

### 3.2 게이트 (라벨을 받은 뒤 기계 검사)

| 검사 | 방법 | 실패 시 |
|---|---|---|
| 지어냄(1번) | 항목 `text` 의 내용어가 단어 k 까지의 Hy 구-접두사 번역에 없으면 위반. 현행 `relabel_adds_en.py` 의 leak 검사를 단어 단위로 옮긴다 | 이유를 붙여 1회 재시도, 두 번 실패하면 그 발화는 뺀다 |
| 완결성(2번) | 이어 붙인 전체를 참조 번역과 비교(COMET-da) 또는 참조가 없으면 원문과 QE(cometkiwi). 현행 gold-anchor 검사 재사용 | 같음 |
| 절 끝 초과(4번) | 항목의 `after_word` 가 그 내용이 속한 절의 마지막 단어보다 크면 위반. 절 경계는 구두점·접속사로 자르고, 없으면 발화 끝 | 같음 |
| 2구 초과(5번) | 구 경계(지금 라벨의 `ends`)를 기준으로, 구 i 의 내용이 구 i+2 끝 뒤에 나오면 위반 | 같음 |

게이트 실패율과 비용은 usage 로그와 함께 `cost_report` 형식으로 집계한다(`.claude/rules/cost-watch.md`).

## 4. 학습 행 생성 (`build_prefix10.py` 를 대체하는 `build_prefix14.py`)

행 하나 = (오디오를 t 초까지 자름, 조건 = t 까지 낸 것, 정답 = t 에 새로 내는 것).

- 자르는 시점 t 는 발화 안에서 0.5초 간격 + 각 항목의 방출 시각(`after_word` 의 끝 시각, 강제 정렬 `word_times`) 직후. 0.5초 간격은 추론 상태를, 방출 시각은 결정 순간을 덮는다.
- t 에서 들린 단어 수 w(t) 를 `word_times` 로 구한다.
- 조건 = `after_word ≤ w(t_prev)` 인 항목들을 순서대로 이어 붙인 것. 정답 = `w(t_prev) < after_word ≤ w(t)` 인 항목들을 이어 붙인 것. 없으면 빈 출력.
- `wait_mid`·`catchup_mid`·`catchup_end` 합성 규칙은 없앤다. "밀린 걸 한 번에"는 같은 t 에 항목이 여럿 열리는 것으로 자연히 생긴다.
- 유지하는 것: 무음 꼬리 행(`sil_end`, 무음에 빈 출력, 환청 방지), 무음 꼬리+밀림 행(`sil_catchup`, 발화 끝에서 남은 전부 내기 — 밀림 상한을 1~2구가 아니라 남은 전부로 넓힌다), `<SEG>` 경계 행, LID 리셋 꼬리 행(prefix13 의 `--reset-rows`).
- 발화 끝 보강: 무음 꼬리 없이 말이 끝나는 순간 잘린 행(VAD 가 닫히는 상태)에 아직 안 낸 전부를 정답으로 넣는다. 발화당 하나.
- 행 수는 prefix13tr(112k)과 같은 자릿수를 목표로 하되, 0.5초 간격 행이 많아지면 발화당 상한(`--rows-per-rec`)으로 깎는다.

## 5. 데이터

두 타깃 모두 **발화 10,000개**. 전량 새 라벨로 교체한다.

| 방향 | 재료 | 발화 | 참조 번역 | 원문 전사 |
|---|---|---|---|---|
| en→ko | FLEURS en train | 1,108 | 없음(라벨러가 씀, 지금과 같음) | 있음 |
| en→ko | CoVoST2 train en (이미 쓰던 6,892 + 로컬에 남은 8,108 중 2,000) | 8,892 | 없음(같음) | 있음 |
| ko→en | FLEURS ko train | 1,984 | 있음 | 있음 |
| ko→en | **kosp2e train** (상류 분할 106,653 중 8,016) | 8,016 | **있음(en)** | **없음** → qwen-seg(`Qwen3-ASR-1.7B-koen-seg-mix-merged`)로 오프라인 전사 후 강제 정렬 |

kosp2e 구성(내 선택, 구어체 비중을 높임): stylekqc 3,000 / covid 2,000 / zeroth 2,000 / kss 1,016. kss·covid 는 비상업·학술용 라이선스. test 분할(2,320)은 벤치용이라 쓰지 않는다. 설치는 `datasets/kosp2e/install.sh` 가 `data/<corpus>_train.xlsx` 의 행만 받으므로, 뽑은 행만 남긴 xlsx 를 미리 놓는다. 1개/초라 약 2.5시간, 중단돼도 이어받는다.

zh→en·ja→en(2,255 발화)은 **이번 세대에서 뺀다**(내 선택). en 타깃이 ko 소스 10,000 으로 채워지니 소스 섞임을 없애고 변수를 줄인다. 되살리려면 같은 라벨로 추가하면 된다.

## 6. 라벨 모델과 비용

1차는 **gpt-6-luna** 로 전량(20,000 발화). 실측 단가 $0.00047/호출 → 재시도 포함 **$12~15, 상한 `--budget 20`**. 라벨 형식의 효용이 벤치에서 확인되면 2차로 **gpt-6.1-terra** 전량 교체(실측 $0.0025/호출 → 약 $60~80, 상한 `--budget 100`). terra 는 이번 재라벨에서 첫 통과율이 더 높고 wait 비중이 절반이었다.

호출마다 usage 를 append 하고 누적 비용을 로그에 찍는다. 크래시 뒤 재실행 시 usage 로그를 지우지 않는다.

## 7. 학습·벤치

- SFT·GRPO 는 prefix13tr 과 같은 설정. SFT: LoRA r64/α128, lr 1e-4, 1 epoch, 2×8, `--lazy_features 1`(캐시 없음). GRPO: ceren-lat B 레시피, `--pairs en-ko ko-en`, `--source_tag 0`, 400스텝.
- 벤치는 매니저 queue 로. 설정 `brig.koen+prefix14-lidreset`, `brig.koen+prefix14-grpo-lidreset`(prefix13tr 설정에서 모델 경로만). ko 데이터셋 런 + en 재채점.
- 보고 항목: 관문 표, 잘린 문장 수(길이 비율 <0.6)와 그 COMET, 온전한 문장 COMET, en 발화 중 ko 슬롯 멈춤 횟수, **지어냄 비율**(아래), 비용.

### 7.1 지어냄 지표

출력 조각마다 "조각이 나온 시각보다 뒤에 발화된 원문 단어의 내용"이 들어 있는지를 센다. 정답 분절의 단어별 시각(`reference_alignment`)과 조각의 `decision_audio_sec` 를 쓰고, 내용어 대응은 라벨 게이트와 같은 방식(Hy 구-접두사 번역 대조 또는 참조 번역 정렬)으로 한다. 값은 "조각 수 대비 위반 조각 비율". prefix13tr 런에도 같은 지표를 내서 기준선으로 둔다. 관문은 아니지만 늘어나면 결론에 명시한다.

## 8. 제약

- 모든 체인은 tmux. 비용 발생 단계는 usage 로그 필수.
- 벤치는 매니저 queue 로만(직접 돌리면 S3 에 안 올라감). 설정의 모델 경로는 절대경로.
- 디스크: `--lazy_features 1` 로 전처리 캐시가 안 생긴다. 이전 세대 캐시가 남아 있으면 먼저 지운다.
- 4090 은 공유. GRPO 와 벤치를 겹치면 COMET 서버가 죽는다 — GRPO 가 끝난 뒤 벤치를 넣는다.

## 9. 만드는 사람에게 맡기는 것

- 라벨러 프롬프트의 문장과 예시. 규칙 1~6 은 그대로 넣고, 출력은 JSON 배열 `[{"after": k, "text": "..."}]`.
- 절 경계를 어떻게 자를지(구두점·접속사 규칙)와 그 예외.
- 0.5초 간격 행이 너무 많을 때의 샘플링 방법(`--rows-per-rec`).
- kosp2e 전사에 쓸 배치 스크립트와 강제 정렬 호출(`align_more.py` 재사용 가능).
- 지어냄 지표의 내용어 대응 방식 중 하나 고르기(Hy 대조 vs 참조 정렬). 라벨 게이트와 같은 쪽을 권한다.
